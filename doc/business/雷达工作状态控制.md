业务名称：雷达工作状态控制

业务对象：RadarWorkModeController
- 每个雷达设备一个独立实例（按 deviceId 区分），支持未来多雷达扩展
- 同一设备实例在系统中是单例，由 AppController 装配

触发源：
- UI 按钮（开始 / 待机 / 复位）
- 命令行输入 work / standby / reset（当前无 UI 阶段使用）
- 后续可能由更高层的任务调度自动触发

输入数据：
- 用户请求的目标状态：Working 或 Standby
- 复位请求：reset
- 当前不依赖任何外部回包；未来 ACK 协议出现后再扩展

内部状态：
- Standby   待机，可接收 work 请求
- Starting  启动中，命令已发出但尚未确认
- Working   工作中，可接收 standby 请求
- Stopping  停机中，命令已发出但尚未确认
- Fault     故障，仅接收 reset 请求

状态转换图：
```text
            requestWork (send ok)        timeout / 未来 ACK
   Standby ───────────────────────► Starting ──────────────────► Working
      ▲                                                            │
      │                                                            │
      │ timeout / 未来 ACK                                          │ requestStandby (send ok)
      │                                                            ▼
   Standby ◄──────────────────── Stopping ◄───────────────────── Working

   任意状态下 send 失败 ──► Fault
   Fault  + reset ──► Standby
```

处理规则：
- Standby + requestWork：调用 sender 发送 workStandby=1
  - 发送成功：进入 Starting，启动一次性超时计时器
  - 发送失败：进入 Fault
- Starting + 超时：进入 Working
- Working + requestStandby：调用 sender 发送 workStandby=0
  - 发送成功：进入 Stopping，启动一次性超时计时器
  - 发送失败：进入 Fault
- Stopping + 超时：进入 Standby
- Fault + reset：直接回到 Standby（不发送任何报文，仅复位内部状态）

请求拒绝规则（被拒绝时不改变状态，仅发出 requestRejected 事件）：

| 当前状态 | requestWork | requestStandby | reset |
| --- | --- | --- | --- |
| Standby  | 接受             | 拒绝（重复请求） | 拒绝（仅 Fault 可复位） |
| Starting | 拒绝（过渡中）   | 拒绝（过渡中）   | 拒绝（仅 Fault 可复位） |
| Working  | 拒绝（重复请求） | 接受             | 拒绝（仅 Fault 可复位） |
| Stopping | 拒绝（过渡中）   | 拒绝（过渡中）   | 拒绝（仅 Fault 可复位） |
| Fault    | 拒绝（需先复位） | 拒绝（需先复位） | 接受 |

设计要点：
- **过渡态拒绝所有方向请求**：Starting / Stopping 期间 UI 应禁用按钮，避免乱点
- **Fault 必须显式复位**：避免自动恢复掩盖真实问题
- **重复请求一律忽略**：DPH 已经在保活通道每 50ms 发送，业务命令保持幂等

输出事件：
- stateChanged(oldState, newState)：状态发生真实变化时发出
- workModeCommandIssued(deviceId, mode)：成功向 sender 提交命令时发出
- requestRejected(reason, currentState)：请求被拒绝时发出，便于 UI 给出反馈

超时与未来 ACK：
- 当前为本地计时器实现，默认超时 300ms，可通过 setTransitionTimeoutMs 调整
- 300ms 是 UDP 无 ACK 阶段的临时占位，没有任何业务含义
- 未来加入 ACK 协议时，状态转换由 ACK 报文驱动，原超时改为 ACK 超时阈值
- 测试中通过设置很小的超时值（例如 5ms）来加快状态推进

异常规则：
- sender 返回 false：进入 Fault
- sender 为 nullptr：当前实现视为发送失败，进入 Fault
- 未来 ACK 超时：进入 Fault

落库与日志：
- **不新增数据库表**
- 所有状态变化、命令下发、请求拒绝、进入 Fault 都通过 Logger 记录
- tracks 表仍由 RadarDataProcessor 写入，与本业务无关
- 后续若需要历史查询再考虑独立表

是否影响 UI（后续）：
- 按钮文案：根据 state 切换 "开始 / 待机 / 复位（仅 Fault 显示）"
- 按钮可用性：Starting / Stopping 期间禁用所有业务按钮
- 状态栏：显示当前 state
- 航迹显示：仅在 Working 状态下视为活跃数据

依赖与边界：
- 依赖 IWorkModeCommandSender 抽象，不直接依赖 SystemBus 或 CommunicationManager
- 实际部署使用 BusWorkModeSender，发布 workStandby 到 SystemBus，由 BusToCommRouter 路由到对应端点
- 测试使用 FakeWorkModeCommandSender，可控制返回值并记录调用
