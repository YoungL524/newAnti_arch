# 任务方案与执行记录设计

## 背景

当前 `Task` 同时承担两种概念：

1. **可长期复用的任务方案**（名称、设备绑定、运行参数）
2. **某一次不可复用的执行记录**（操作员、状态、时间戳、数据归属）

代码中 Task 被定义为 one-shot（Completed/Archived 不可重新激活），与用户对「复用任务」的直觉冲突。

## 目标模型

```text
MissionPlan（任务方案，可复用）
        |
        | 创建执行时快照
        v
TaskRun（任务执行记录，一次性、可追溯）
        |
        v
tracks / logs / system_events（归属 taskRunId）
```

UI 层可将 MissionPlan 简称为「任务」，TaskRun 显示为「执行记录」。

## MissionPlan：可复用的任务方案

| 字段 | 说明 |
|------|------|
| id | 方案 ID |
| name | 方案名称 |
| description | 描述 |
| version | 版本号（修改后递增） |
| enabled | 是否启用 |
| deviceIds / device roles | 设备绑定 |
| runtimeSettings | DPH、工作参数 |
| displayPolicy | 航迹样式策略 |
| alertRules | 告警规则 |
| geofence | 工作区域 |
| forwardingRules | 数据转发规则 |
| createdAt / updatedAt | 时间戳 |

语义：**这个地方/业务长期应该怎么运行**。雷达长期部署在同一地点时，MissionPlan 可一直复用。

## TaskRun：一次任务执行记录

| 字段 | 说明 |
|------|------|
| id | 执行记录 ID（当前 DB 的 `tasks.id`，迁移期语义为 taskRunId） |
| missionPlanId | 来源方案（legacy 可为 NULL） |
| missionPlanVersion | 激活时方案版本 |
| planSnapshotJson | 不可变方案快照 |
| operatorName | 操作员 |
| status | 执行状态 |
| startedAt / pausedAt / completedAt | 时间戳 |
| abortReason | 异常中止原因 |
| createdAt | 创建时间 |

语义：**在某个时间段，谁使用哪一版任务方案执行了一次业务**。

数据库字段 `task_id` 在迁移期保留，语义明确为 **taskRunId**，不是 MissionPlan id。

## 生命周期规则

### 是否每次开机都要新建任务？

**不应该。** 后端启动时会查询 `Active` task 并刷新 `ActiveTaskContext`，未完成的执行可恢复。

建议规则：

```text
同一业务目标长期存在  → 复用 MissionPlan
同一次连续值守/行动   → 使用同一 TaskRun
应用重启             → 恢复未完成的 Active/Suspended TaskRun
明确完成一次行动       → 结束 TaskRun
下一次行动           → 从同一 MissionPlan 创建新 TaskRun
```

### TaskRun 状态机（目标）

```text
Draft -> Active <-> Suspended -> Completed
                         \-> Aborted
Completed/Aborted -> Archived
```

- Stop acquisition ≠ Complete TaskRun
- 应用重启可恢复 Active，或转为 Suspended 等待确认
- 操作员主动结束 → Completed
- 异常中止 → Aborted

当前实现仍为 `Draft -> Active -> Completed -> Archived`，Suspended/Aborted 在 Milestone D 引入。

## 前端查看维度

| 变量 | 用途 |
|------|------|
| activeTaskRunId | 当前运行中的执行记录；控制实时采集与实时航迹 |
| viewTaskRunId | 当前查看的历史执行记录；控制历史航迹、系统事件 |

规则：

- 查看 Completed/Archived TaskRun **不改变** activeTaskRunId
- 可一边运行任务 A，一边查看任务 B 的历史（UI 须明确处于历史查看模式）
- 新建任务时显式选择设备；不复用「复制设备列表」冒充方案复用

## 删除与归档

| 场景 | 策略 |
|------|------|
| 有 tracks/system_events 数据 | 禁止物理删除，仅允许归档 |
| Draft 且从未执行 | 允许物理删除 |
| Active | 禁止删除 |

TaskRun 激活时应生成不可变快照（plan_snapshot_json、device_snapshot_json 等），避免事后修改 MissionPlan 导致历史语义漂移。

## 真正的「复用业务逻辑」

```text
选择 MissionPlan
  -> 加载设备角色、运行参数、告警规则、显示策略、区域和转发规则
  -> 创建新的 TaskRun
  -> 把当前方案版本做成不可变快照
  -> 本次航迹/日志/事件归属新 TaskRun
```

要点：

- 复用配置，不复用历史数据
- 复用 MissionPlan，不重新激活 Completed TaskRun
- TaskRun 创建后保存方案快照，后续修改 MissionPlan 不篡改历史执行语义
