# 航迹显示数据管理

## 概述

上位机不负责航迹起批、消失、融合等算法（属于数据处理系统职责）。上位机负责的是航迹显示数据管理：接收 `RadarDataProcessor` 输出的航迹点，转为固定 Web 协议，维护显示状态。

## 架构边界

```
endpointId
  → RadarDataProcessor 查询 DeviceRegistry / endpoint binding
  → TrackPoint.deviceId = 业务设备 id（端到端链路只传递 deviceId，不传递 endpointId）
  → TrackDisplayManager 只接收 TrackPoint，不关心 endpointId
  → TrackDisplaySnapshot（固定 Web 协议，全量 snapshot）
  → WebApiController / WS → 前端
```

关键依赖：
- `TrackPoint.deviceId` 必须是 `DeviceRegistry` 业务设备 id（如 `radar_001`）
- `endpointId → deviceId` 映射由 `RadarDataProcessor` 完成，`TrackDisplayManager` 不接触 endpoint
- WS 消息为全量 snapshot（每 1s 推当前显示窗口内所有点）
- TrackDisplayManager 内部状态索引使用复合 key `(deviceId, trackId)`

## TrackPoint — 内部模型（C++）

```cpp
struct TrackPoint {
    QString deviceId;            // DeviceRegistry 业务设备 id（RadarDataProcessor 完成映射）
    uint32_t trackId;            // 航迹号
    qint64 timestampMs;
    double range;
    double azimuth;              // rad
    double elevation;            // rad
    double radialSpeed;
    double rcs;
    double altitude;
    double x, y, z;
    uint32_t sceneNumber;
};
```

- `RadarDataProcessor` 输出此结构后，后续模块不接触 `GeneralPackage`/`TargetType`
- `deviceId` 在 `RadarDataProcessor` 内通过 `endpointId → DeviceRegistry` 查询完成
- `TrackDisplayManager` 不查询 `DeviceRegistry`，不关心 `endpointId`

## 显示缓存保留策略

上位机不判断航迹是否在物理上消失。但显示层必须有缓存保留策略：

- 每条 `(deviceId, trackId)` 最多保留 500 个点
- 同时按时间窗口限制：最近 60s
- 单次 snapshot 最多输出 5000 个点；超过时只裁剪本次输出集合（不影响 TrackDisplayManager 内部缓存）
- 超出限制时丢弃最旧的点（FIFO）

## WS 消息格式（全量 snapshot）

```typescript
interface WsTrackSnapshotMessage {
  type: 'tracks'
  mode: 'snapshot'
  timestamp: number
  tracks: TrackDisplayPoint[]
}

interface TrackDisplayPoint {
  trackId: number
  deviceId: string              // DeviceRegistry 业务设备 id
  timestamp: number

  range: number
  azimuth: number
  elevation: number
  x: number; y: number; z: number
  radialSpeed: number
  rcs: number

  // 显示状态
  pointIndex: number            // 该 (deviceId, trackId) 自接收以来绝对递增序号
                                // 不是缓存数组下标，FIFO 裁剪后不会重置
  style: {
    color: string
    size: number
    opacity: number
  }
  interaction: {
    selected: boolean
    trackingEnabled: boolean
  }
  routing?: {
    forwardTo?: string
  }
}
```

## TrackDisplayManager 内部状态

```cpp
struct TrackKey {
    QString deviceId;
    uint32_t trackId;
};
```

- 内部 interaction map 及缓存均以 `TrackKey` 为索引
- 不用裸 `trackId`，避免多设备同航迹号冲突

## TrackDisplayManager 职责

- 接收 `TrackPoint`（已含业务 `deviceId`）
- 按 `TrackKey` 维护点序列和绝对递增 `pointIndex`
- 根据缓存保留策略（500 点 / 60s / 5000 snapshot 上限）丢弃旧点
- 管理 `interaction` 状态
- 根据 `pointIndex` 和用户交互状态生成 `style`
- 每 1s 输出 `TrackDisplaySnapshot`（全量当前可见点）

非职责：
- 不查询 `DeviceRegistry`
- 不关心 `endpointId`
- 不判断航迹起批、消失、融合
- 不做目标识别

## Interaction 状态更新

interaction 状态在 `TrackDisplayManager` 内部通过复合 key 维护。

```http
PUT /api/devices/{deviceId}/tracks/{trackId}/interaction
Content-Type: application/json

{
  "selected": true,
  "trackingEnabled": false
}
```

响应：

```json
{
  "ok": true,
  "interaction": {
    "selected": true,
    "trackingEnabled": false
  }
}
```

- 更新后 `TrackDisplayManager` 更新指定 `(deviceId, trackId)` 的 interaction 状态
- 下次 snapshot 输出时将携带更新后的 interaction
- `selected` 与 `trackingEnabled` 独立存储

## endpointId 映射约束

`endpointId → deviceId` 映射必须唯一：

```
对于会产生航迹数据的采集 endpoint，同一时刻只能绑定一个 Radar 业务设备。
```

- `DeviceRegistry::findRadarByEndpointId(endpointId)` 提供按端点查询接口（只匹配 Radar 设备）
- 非空 `endpointId` 在 `create`/`update` 时做应用层冲突检查（同 kind=Radar 不重复）
- 如果 `RadarDataProcessor` 收到数据但 `endpointId` 未绑定 Radar 业务设备：丢弃该 `TrackPoint`，不向 `TrackDisplayManager` 输出
- 如果 `endpointId` 绑定多个 Radar 业务设备：记录 `qWarning`，返回空映射，`RadarDataProcessor` 丢弃该 `TrackPoint`（宁可不显示，不挂错设备）

## 与现有模块的关系

- `RadarDataProcessor`：适配 `GeneralPackage` → `TrackPoint`，查询 `DeviceRegistry` 填入业务 `deviceId`
- `TrackDisplayManager`：新建模块，接收 `TrackPoint`，输出 `TrackDisplaySnapshot`
- `WebApiController`：不再直接引用 `GeneralPackage`/`TargetType`，从 `TrackDisplayManager` 获取 snapshot 并推送

### 前端迁移注意

- `useCoreApi.tsx`：`msg.type === 'tracks'` 当前是增量追加 `[...tracksRef.current, row].slice(-500)`。
  改为 snapshot 后应以 `msg.tracks` 替换当前显示数据，不再 append。
- `trackRate` 不能再简单 `++`，应改为 snapshot 点数或由后端提供统计字段。
- `DataTable` 如需展示"航迹列表"而非"点列表"，应按 `(deviceId, trackId)` 聚合最后一个点。
- `TrackLayer`（前端 canvas）仍为渲染层，数据格式改为全量 `TrackDisplayPoint[]`，每次 snapshot 替换上一帧。
