# 航迹显示数据管理

## 概述

上位机不负责航迹起批、消失、融合等算法（属于数据处理系统职责）。上位机负责的是航迹显示数据管理：接收 `RadarDataProcessor` 输出的航迹点，转为固定 Web 协议，维护显示状态。

## 架构边界

```
GeneralPackage → RadarDataProcessor(协议适配)
  → TrackPoint(内部通用格式)
  → TrackDisplayManager(显示状态管理)
  → TrackDisplaySnapshot(固定 Web 协议)
  → WebApiController / WS → 前端
```

- `RadarDataProcessor` 保持协议适配职责，只把 `GeneralPackage` 转为 `TrackPoint`
- `TrackDisplayManager` 订阅/接收 `TrackPoint`，产出 `TrackDisplaySnapshot`
- `WebApiController` 推送的 `tracks` 消息改为由 `TrackDisplayManager` 输出的 snapshot
- 厂家协议差异在 `protocol` + `RadarDataProcessor` 内部消化，Web 只接收固定协议

## 固定 Web 协议（TrackDisplaySnapshot）

```typescript
interface TrackDisplayPoint {
  trackId: number          // 航迹 id
  deviceId: string         // 设备业务 id
  timestamp: number        // 时间戳

  // 坐标
  range: number            // 斜距 (m)
  azimuth: number          // 方位角 (rad)
  elevation: number        // 俯仰角 (rad)
  x: number; y: number; z: number

  // 运动
  radialSpeed: number      // 径向速度
  rcs: number              // RCS

  // 显示状态（由 TrackDisplayManager 管理）
  pointIndex: number       // 该目标第 N 个点（用于区分前 N 个点与稳定点）
  style: {
    color: string          // 颜色
    size: number           // 尺寸
    opacity: number        // 透明度
  }
  interaction: {
    selected: boolean      // 是否被用户选中
    trackingEnabled: boolean // 追踪使能
  }
  routing?: {
    forwardTo?: string     // 数据转发目标
  }
}
```

## TrackDisplayManager 职责

- 接收 `TrackPoint`（从 `RadarDataProcessor` 或 SystemBus）
- 按 `trackId` 维护点序列和 `pointIndex`
- 根据点序号、用户交互状态生成 `style`
- 输出 `TrackDisplaySnapshot` 供 API/WS 推送
- 1s 节流输出（与前端显示刷新率对齐）

非职责：
- 不判断航迹起批、消失、融合
- 不做目标识别
- 不修改雷达协议数据

## 状态转换

```
TrackPoint 到达
  → 查找或创建 trackId 记录
  → 追加点，递增 pointIndex
  → 生成 style（前 3 个点用强调色，后续用标准色）
  → 合并 interaction 状态（保持用户操作不变）
  → 产出 TrackDisplaySnapshot
  → 推送 WS / 缓存待查询
```

## 与现有模块的关系

- `RadarDataProcessor`：保持通用包→ `TrackPoint` 适配关系
- `WebApiController`：不再直接引用 `GeneralPackage`/`TargetType`，接收 `TrackDisplaySnapshot` 并序列化
- `TrackLayer`（前端）：仍为 canvas 渲染层，数据格式改为 `TrackDisplayPoint[]`
- `DataTable`（前端）：仍显示航迹列表，数据源改为 snapshot
