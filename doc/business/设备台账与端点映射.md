# 设备台账与端点映射

## 概述

业务设备台账由后端 `DeviceRegistry` 管理，持久化在 SQLite `devices` 表中。前端设备列表必须来自 `/api/devices`。

**核心原则**：`endpoints.json` 描述通信配置，设备台账描述业务设备，两者通过 `endpointId` 关联。
前端无法控制的 fallback/临时设备不允许进入正式设备列表、任务关联和控制链路。

## 设备存储位置

- 数据库配置：`config/database.json`
- 默认 SQLite：`data/antidrone.db`
- 设备表：`devices`
- 后端归口：`core/business/DeviceRegistry`

### 排查 SQL

```sql
SELECT id, name, kind, brand, endpoint_id, linked_radar_id, status
FROM devices
ORDER BY created_at;
```

### 设备身份规则

1. 设备业务 id 由后端 `DeviceRegistry` 确认。前端临时 id 只允许存在于未保存草稿。
2. `endpointId` 是设备能否控制真实端点的唯一绑定入口。无 `endpointId` 的设备不可采集。
3. 任务、控制命令、航迹归属均引用后端确认的 `deviceId`。
4. `POST /api/devices` 返回后端确认后的完整 `DeviceInfo`，前端以返回值中的 id 和字段为准。

## 数据模型

### DeviceInfo

```cpp
enum class DeviceKind { Radar, Opto, Level, Gps };
enum class DeviceStatus { Offline, Standby, Working, Fault };

struct DeviceInfo {
    std::string id;
    std::string name;
    std::string brand;           // cetc38 / cetc14 / leiying
    DeviceKind kind;
    double lng = 0;
    double lat = 0;
    double altitude = 0;
    double pitch = 0;           // 整机俯仰，抬头为正
    double roll = 0;            // 整机横滚，右侧下沉为正
    double maxRange = 0;         // km, radar only
    std::string facesJson;       // JSON array of face configs, radar only
    std::string endpointId;      // link to endpoints.json
    std::string linkedRadarId;   // for sub-devices
    double mountOffsetAzimuth = 0;
    std::string coordinateSystem = "WGS-84";
    DeviceStatus status = DeviceStatus::Offline;
};
```

### SQLite 表

```sql
CREATE TABLE IF NOT EXISTS devices (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    brand TEXT,
    kind INTEGER NOT NULL DEFAULT 0,
    lng REAL DEFAULT 0,
    lat REAL DEFAULT 0,
    altitude REAL DEFAULT 0,
    pitch REAL DEFAULT 0,
    roll REAL DEFAULT 0,
    max_range REAL DEFAULT 0,
    faces_json TEXT DEFAULT '[]',
    endpoint_id TEXT DEFAULT '',
    linked_radar_id TEXT DEFAULT '',
    mount_offset_azimuth REAL DEFAULT 0,
    coordinate_system TEXT DEFAULT 'WGS-84',
    status INTEGER DEFAULT 0,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

## 架构边界

```
endpoints.json        → 通信配置（UDP 端点）
DeviceRegistry        → 业务设备台账（SQLite）
RadarWorkModeController → 设备运行状态机
WebApiController      → API 表现层
```

## API

| 方法     | 路径                | 说明     |
| ------ | ----------------- | ------ |
| GET    | /api/devices      | 列出所有设备 |
| POST   | /api/devices      | 创建设备   |
| PUT    | /api/devices/{id} | 更新设备   |
| DELETE | /api/devices/{id} | 删除设备   |

设备状态由后端运行时更新，不通过 API 直接修改。

## 与前端的关系

- 前端启动时 `GET /api/devices` 加载设备列表
- 前端添加/编辑/删除设备 → 调对应 API → 成功后更新本地状态
- 前端保留当前 UI，数据源从 localStorage 改为后端 API
- 任务系统仍可前端管理，但设备关联通过后端 ID 完成

## 雷达位姿与阵面角度契约

雷达位姿由经度、纬度、海拔、`pitch`、`roll` 与阵面绝对朝向组成。
厂家协议中的航迹方位角和俯仰角属于雷达本地坐标，显示前必须经过整机姿态旋转，
再投影到本地 ENU（East/North/Up）和 WGS-84 经纬度。

- 航迹方位角：0° 指向雷达机体前方，顺时针为正；
- `pitch`：机体抬头为正；
- `roll`：机体右侧下沉为正；
- `facesJson[].boresightAzimuth`：阵面安装完成后测得的绝对朝向；
- 航向只保存在阵面配置中，直接使用现场测得的绝对值，不与其他角度叠加。

当前航迹协议没有阵面 ID。只有一个活动阵面时，航迹投影使用该阵面的绝对朝向；
存在多个活动阵面时不猜测航迹来源，不附加朝向修正。多阵面精确投影需要协议补充 `faceId`。
