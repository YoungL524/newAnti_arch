# 运行时参数管理

## 概述

`DPH`（Data Package Header）是每 50ms 发送给雷达 CPU 的外部协议结构体，不是 UI model。`RuntimeSettingsService` 是内部运行时参数模型，UI 只与此模型交互，不直接接触协议结构体。

## 设计原则

- 前端不改参数就不发事件；后端继续使用上一次有效参数
- `DphPublisher` 每 50ms 只使用最新缓存发送，不主动向 UI 或 API 拉取
- UI 修改参数 → API → `RuntimeSettingsService` → 事件 → `DphPublisher` 更新本地缓存
- 不落库（当前阶段），运行时参数只存在内存中

## 数据流

```
UI 参数编辑
  → WebApiController
  → RuntimeSettingsService
  → DphParamsChanged event (通过 SystemBus 发布)
  → DphPublisher 更新本地缓存
  → QTimer 每 50ms 使用缓存组 DPH 并发送到 UDP 端点
```

## 架构边界

```
UI  → 修改参数  → RuntimeSettingsService → SystemBus event → DphPublisher
UI  ← 读取当前参数 ← RuntimeSettingsService
DPH 协议结构体 ← DphPublisher adapter ← 内部运行时快照
```

- `RuntimeSettingsService` 持有当前有效参数快照
- `DphPublisher` 不直接访问 `RuntimeSettingsService`，只响应 `DphParamsChanged` 事件
- 前端不直接理解 `DataPackageHeader` 字段，只通过 API 读写运行时参数 DTO

## 最小 DTO（第一阶段）

```cpp
struct RadarRuntimeSettings {
    uint32_t workMode = 0;          // 0=standby, 1=work
    uint32_t sceneNumber = 1;       // 景幅序号
    // 后续扩展：天线模式、频率、波形等
};
```

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/runtime-settings | 读取当前运行时参数 |
| PUT | /api/runtime-settings | 更新运行时参数（触发事件） |

## 与现有模块的关系

- `DphPublisher` 不再从固定默认值构造 `DataPackageHeader`，改为从缓存读取
- `DphPublisher` 新增 `applyRuntimeSettings(const RadarRuntimeSettings&)` 方法
- `DphParamsChanged` 事件通过 SystemBus 的 `DataPacket` 机制发布
- 不影响 `RadarWorkModeController`（工作模式状态机仍独立运行）
- 不影响 `RadarDataProcessor`（航迹处理不依赖运行时参数）
