雷达工作状态控制
← / → 键切换 空格键下一页

概述

控制雷达进入工作模式（开始上报航迹）或待机模式（停止上报）。web 端”开始采集”/“停止采集”按钮和 core 控制台输入均可触发。

协议层约定：workStandby_Mode = 1 为工作，0 为待机。这条 DPH 报文通过 UDP 每 50ms 持续发送给雷达 CPU，雷达根据 Mode 字段决定是否上报航迹数据。

触发路径

用户可通过两个入口触发状态切换，底层统一到达 RadarWorkModeController：

Web UI 按钮点击                        core 控制台输入
     │                                       │
     ▼                                       ▼
POST /api/start (工作)               stdin: "1" 或 "work"
POST /api/stop  (待机)               stdin: "2" 或 "standby"
     │                                       │
     ▼                                       ▼
RadarWorkModeController.requestWork()    requestStandby()
     │
     ▼
IWorkModeCommandSender.sendWorkMode(deviceId, mode)
     │
     ▼
BusWorkModeSender → SystemBus.publish(DataPacket)
     │
     ▼
BusToCommRouter → CommManager.sendTo("dph") → UDP → 雷达 CPU

输入值约定

输入值 含义 HTTP 端点 stdin 命令
workStandby_Mode = 1 工作（开始上报航迹） POST /api/start 1 / work
workStandby_Mode = 0 待机（停止上报航迹） POST /api/stop 2 / standby

状态机

            requestWork (send ok)
  Standby ───────────────────────► Starting ───(超时 300ms)──► Working
     ▲                                                           │
     │                                              requestStandby (send ok)
     │                                                           │
     │                                                           ▼
  Standby ◄─────────────────────── Stopping ◄──(超时 300ms)─── Working

  任意状态 + send 失败 ──► Fault
  Fault   + reset ──► Standby
状态 含义 web UI 表现
Standby 待机，可接收 work 请求 按钮显示”开始采集”，可点击
Starting 命令已发出，等待确认 按钮禁用（过渡中）
Working 工作中，雷达上报航迹 按钮显示”停止采集”，可点击
Stopping 停机命令已发出 按钮禁用（过渡中）
Fault 故障，需显式复位 按钮显示”复位”，仅此可点击

请求接受/拒绝矩阵

当前状态 requestWork requestStandby reset
Standby 接受 拒绝 拒绝
Starting 拒绝 拒绝 拒绝
Working 拒绝 接受 拒绝
Stopping 拒绝 拒绝 拒绝
Fault 拒绝 拒绝 接受
  • 过渡态（Starting/Stopping）拒绝所有新请求，web 端按钮在此期间禁用
  • 重复请求（如在 Working 状态再点”开始采集”）直接忽略
  • Fault 必须显式复位，不自动恢复

前端联动

前端 useCoreApi 通过两个渠道同步状态：

  1. HTTP 轮询（每 5 秒）：GET /api/status → { acquisition, state, connected }
  2. WebSocket 推送（每 1 秒）：{ type: "status", acquisition, state, connected }

采集按钮行为： - 当前 acquisition === false → 点击 → POST /api/start → 乐观更新为 true - 当前 acquisition === true → 点击 → POST /api/stop → 乐观更新为 false - 乐观更新后若后端拒绝，下一次轮询/推送会恢复到实际状态

异常处理

异常 结果 恢复方式
sender 为 nullptr 进入 Fault 复位
send 返回 false 进入 Fault 复位
未来 ACK 超时 进入 Fault 复位
后端未运行（前端 fetch 失败） 静默忽略，下次轮询恢复 启动 core.exe

输出事件

  • stateChanged(old, new) — web 端可通过 WS 监听到状态变化
  • workModeCommandIssued(deviceId, mode) — 命令成功提交到总线的记录
  • requestRejected(reason, currentState) — UI 可据此给出反馈

设计要点

  • DPH 持续发送：DphPublisher 每 50ms 独立发送 DPH 报文，不受状态机影响。状态机只改变报文中的 workStandby_Mode 字段
  • 幂等：重复发送相同 workStandby_Mode 的 DPH 不会造成问题，雷达端忽略重复命令
  • 过渡态保护：Starting/Stopping 期间锁定所有输入，防止 web 端快速点击或 stdin 乱序输入
  • 超时值 300ms 无业务含义：当前为 UDP 无 ACK 阶段的临时占位，后续引入 ACK 协议后改为 ACK 驱动状态转换

日志

  • 所有状态变化、命令下发、请求拒绝、异常进入 Fault 均通过 Logger 写入日志文件
  • 日志格式：[RadarWorkModeController] <event> detail=...
  • 不新增数据库表，不写入 SQLite

依赖

RadarWorkModeController
  ├── IWorkModeCommandSender (抽象接口)
  │     └── BusWorkModeSender (生产实现)
  │           └── SystemBus::publish()
  └── QTimer (过渡超时)

不直接依赖 CommunicationManager、HttpServer 或任何 UI 组件。
