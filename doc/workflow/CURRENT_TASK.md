# 当前任务：Python GUI 模拟 0x0100 单目标航迹

## 状态

三个基础链路已由用户运行确认；细节待逐项设计，代理未编译或运行测试。

## 合同

- 用户点击“开始采集”，本地采集成功后由唯一 `DeviceController` 向 `127.0.0.1:1234` 发一包 68 字节 `0xFFFF`，`workStandbyMode=1`。
- 用户点击“停止采集”，本地采集成功结束后向同一目标发一包，`workStandbyMode=0`。不受 DP/SP 心跳门控，不等待 ACK、设备执行确认，也不创建 FIFO 或重试。
- `0x0001` 在任务激活且 DP/SP 都在线时每 50 ms 发送；开始/停止采集不控制该周期，完成任务才撤销快照。界面修改参数时替换下一周期的完整快照。
- 同一内部 UDP 端点收 DP/SP 心跳和 DP 航迹，也向 DP 发两种命令；其 Socket 和组合根实例命名为 `m_sock2DpSp`，不为 SP 单独创建套接字。

## 实现与静态核对

- `DcmpProtocolAdapter::encodeWorkMode(bool)` 逐字段生成 44 字节公共头、20 字节载荷和 4 字节包尾，声明长度 56；保留字零填充。
- `DeviceController::beginAcquisition/endAcquisition` 在本地状态切换成功后各调用一次发送函数；同一发送回调复用现有 UDP 端点。
- 任务激活后准备 `0x0001` 快照并固定向 `127.0.0.1:2345` 发送；准备失败撤销 Ready 选择。任务完成清除快照，任一心跳离线立即停发。
- Python 心跳包按 44 字节公共头、84 字节载荷、4 字节包尾组成，和 Core 静态接收合同一致；当前单面阵模拟只置阵面位图 bit0 (`0x01`)；GUI 分别监听 2345 和 1234，并显示已提交心跳次数。
- Python GUI 联试工具分别在 `127.0.0.1:2345` 和 `127.0.0.1:1234` 接收两种报文；使用说明见 `tools/README.md`。
- GUI 使用现有心跳发送 Socket 按 200 ms 周期发送 656 字节 `0x0100`，固定 1 号阵面、目标 ID 1；停止时发送 `packFlag=0`，不伪造任务、设备或会话身份。
- 代理不编译、不运行测试；本轮只进行中文 Doxygen 审计、Python AST 解析和静态差异检查。

## 2026-09-29 静态复核结论

- 三条新增链路未引入第二个命令 Owner、中央消息总线、控制队列或第二份航迹历史；设备侧 Python GUI 独立于正式运行链。
- 当前变更未新增推测性后端类型或层级；协议编码仍在 Adapter 边界，周期状态仍由 DeviceController 独占。
- 已知后续细化项：UI 转换显示点时丢弃 `acquisitionId`，地图仅按 `trackId` 分组；停止再开始采集后，新旧会话同号航迹会被连在一起。本轮按用户要求暂不修改显示规则。

## 用户验收

1. 启动 Python 窗口，同时监听 `127.0.0.1:2345` 和 `127.0.0.1:1234`。开始采集后恰收到一次 `0xFFFF` 值 1，停止后恰收到一次值 0；包长 68、声明长度 56、保留字全零。
2. 未激活任务时即使双心跳在线也没有 `0x0001`；激活后双心跳在线即周期发送，停止采集后仍继续，任一心跳离线或完成任务后停止。
3. UDP 本地提交失败时本地采集状态不回滚，但须有错误诊断。以上均待用户实际运行反馈。
4. 开始采集且任务启用 1 号阵面时打开模拟航迹，地图应出现一条移动航迹；关闭模拟后目标应被消亡包移除。未开始采集时即使 Python 发送，Core 也不得发布该航迹。
