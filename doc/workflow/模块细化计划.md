# DCMP 模块细化计划

更新：2026-10-16。目标是逐模块完成业务细节并固化，全部完成后再做整体部署；本文件不自动授权开工。

## 当前七个模块与建议顺序

| 顺序 | 模块 | 当前实现与代码入口 | 细化重点与完成边界 |
| --- | --- | --- | --- |
| 1 | 数据归档、查询与回放 | core/archive、core/persistence；ui/src/hooks/useTrackReplay.ts、ui/src/lib/historyApi.ts | 先调整“数据回放/日志归档”入口职责；再完善筛选、分页、时间轴、播放/定位及错误提示。只读历史不改变任务或设备状态，保持会话/阵面隔离与安装 revision 重建语义。 |
| 2 | 实时航迹与地图展示 | TrackIngressProducer、TrackWebSocketService；MapRadarView、TrackLayer、DataTable | 航迹标识、选择、尾迹、消亡、表格字段、实时刷新与回放视觉一致性；保持现行容量预算和在线/离线引擎边界，流畅度优化先测量。 |
| 3 | 设备管理与状态 | core/config、DeviceController；设备编辑窗口、状态栏 | 设备字段、安装姿态、revision 冲突、软删除、阵面选择、DP/SP/FP 状态含义与界面反馈；不混淆通信在线和本地采集状态。 |
| 4 | 任务与采集流程 | core/task、ApplicationController、StorageRuntime；任务创建、侧栏、标题栏 | 模板、创建/激活/启停/完成/归档、参数快照及失败回滚；完成多阵面整组会话和重连状态交互验收，不引入第二个状态 Owner。 |
| 5 | 雷达协议与设备控制 | core/protocol、core/comm、DeviceController；控制参数窗口、tools/control_link_gui.py | 逐字段核对现行协议及 UI 映射，明确参数应用结果、心跳门控与发送失败；保持 0x0001/0xFFFF 合同。RF 复位等未决动作先确认真实业务，不能推测实现。 |
| 6 | 事件、系统日志与运行记录 | SystemEventPublisher、EventWebSocketService；ArchiveEventsDialog、ArchiveRunsDialog | 级别、域、关联身份、筛选分页、错误可读性和归档状态；业务事件单链，低层诊断仅排障，清楚区分运行标记与进程存活。 |
| 7 | 基础运行与资源边界 | ApplicationRuntime、SystemStateOwner、CoreDataDomain、ExecutionLane、Core HTTP/WS | 启停、重连、接口失败边界、退避、容量/gap、在途关停及真实负载指标；以测量修缺陷，不重新搭建抽象框架。 |

基础共享域是各模块共同依赖，顺序 7 是最终复核资源和生命周期，不能等到最后才修影响前面模块的基础缺陷。
模块划分是工作范围，不是增加七套服务、线程、队列或消息类型。

## 每个模块的固定流程

1. 先确认本模块的实际业务、输入输出、唯一 Owner、现有合同与可复现问题，限定本次范围。
2. 更新必要合同并实施最小改动，维护中文 Doxygen；代理执行定向静态检查，不编译或运行测试。
3. 用户编译及运行确认：正常路径、拒绝/失败路径、状态同步、历史隔离和必要的负载边界。
4. 用户确认后更新当前交接并提交推送，为该模块创建独立固化标签；后续修改不得静默破坏已固化合同。

第一项开工时先确认侧栏“数据回放”和“日志归档”各自承载的入口，复用同一历史查询/回放数据源，
不复制航迹历史、不因切换入口触发采集或改变设备状态。识别算法、光电、插件、融合、多雷达和外部转发
不在当前已实现模块的细化范围，须有实际需求与协议后单独安排。

## 所有模块完成后的整体部署

整合已固化模块 → 用户构建完整 Core/UI → 收集到全新部署目录 → 校验配置、地图、字体和清单 →
干净电脑安装/运行 → 正常与异常退出、升级保留数据库、离线运行及现场 DP/SP 联试 → 固化交付版本。
现有启动器/打包脚本作为基础复用；当前 release-fixed 继续保留，不能用本次源码固化冒充部署包已更新。
