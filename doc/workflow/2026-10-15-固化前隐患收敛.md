# 固化前隐患收敛（2026-10-15）

用户授权：依据评审先收敛，再提交推送一版至 GitHub，之后按模块细化。本版是源码基线，未经编译或运行验收，
不能因已提交或推送而标记生产验收完成。独立协议 Excel 和用户提供的 PDF 评估原件留在本地，不纳入本次提交。

## 本轮处理

1. 会话创建与停止改为整组 SQLite 事务，提交后统一更新内存活动位；启动后绑定失败使用 Error 收口，
   清理失败明确返回并发布 Faulted。Producer 停止后的正常关停以 ProcessShutdown 收口所有活动会话再排空归档，
   closeCleanly 额外拒绝仍有活动会话的 run。启动兼容修复旧正常 run 遗留会话，只用已记录的正常退出时间。
2. SQLite 恢复之前按规范化数据库路径获取 QLockFile，覆盖直接 EXE 与启动器两条启动方式；关闭连接后释放。
   不使用按锁文件年龄强制接管，不修改仍存活 Core 的运行记录。IPC 无效/超长行只丢弃并记录，超长尾部不解释成 STOP；
   真正管理连接断开仍按原合同正常退出。HTTP 显式拒绝重复 Content-Length 和 Transfer-Encoding，原容量预算保持。
3. Web 近期显示保持每目标 20 点，批次结束最多 256 目标，按最后观测次序淘汰；retirement/removals 只影响显示。
   浏览器每目标旧路径合计最多 2048 点，全页 32768 点；裁剪旧前缀，不增加 TTL、线程、Topic 或第二份历史。
   同批消亡后重建复用点序号时，早先删除键不能覆盖新 upsert；断线取消 RAF 并清空旧会话缓存，snapshot 替换旧形状。
4. 实时不再补零高度、SNR、信号、景幅和外推，不使用厂家号冒充识别类别；Unknown=0。
   历史海拔明确标为安装配置重建，厂家幅值标为原值；表格派生改 useMemo，完整 RAF 批次只派生一次显示。

## 保留的架构决定

不按外部报告重写 CAS、改用 shared_ptr 历史槽位、lock-free、第二存储连接或额外实时线程。
不引入 CQRS 包装层、WebSocket 订阅协议、固定 60 秒目标 TTL，也不声称未经测量的吞吐提升。
现有数据域、固定 ScratchBuffer、Lane 合并、唯一 DeviceController 命令链及 UDP 本地提交语义保持。

## 验证与后续

代理仅做类型、中文 Doxygen、差异、调用点和失败路径静态复核；未编译、运行测试、启动服务或新增测试程序。
运行验收沿用 [系统闭环验收](2026-10-15-系统闭环验收.md)，额外核对：

- 采集中正常关闭再启动后，旧会话为 ProcessShutdown，旧任务可以继续完成；旧版正常 run 遗留会话得到兼容收口。
- 四面阵任一停止更新失败时，四面数据库与内存均不部分停止；解除故障可再次停止。
- 同库第二个 Core 拒绝启动且不修改第一个 run/会话；首个正常关闭后可重启，崩溃后可恢复进程锁。
- 超过 256 显示目标、长时间曲折航迹、消亡号复用和断线重连下容量有界，无幽灵目标；归档仍包含全部合法观测。
- 实时缺失字段为空，历史重建高度单位明确，图层和表格沿用同一最终事实。

数据回放与日志归档入口的职责调整已确认方向，但本轮不迁移入口；作为随后首个模块细化事项。
