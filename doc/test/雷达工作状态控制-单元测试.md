业务名称：雷达工作状态控制
被测对象：RadarWorkModeController
测试框架：Qt Test (Qt5::Test)
测试源码：doc/test/src/tst_RadarWorkModeController.cpp

## 一、测试目标

证明 RadarWorkModeController 在所有定义的输入下都符合业务文档中的状态机规则：

- 正确响应合法请求并切换状态
- 正确拒绝非法请求并保持状态不变
- 正确发出 stateChanged / workModeCommandIssued / requestRejected 事件
- 发送失败时进入 Fault
- Fault 仅响应 reset

## 二、测试夹具

- FakeWorkModeCommandSender：测试用 sender，可设置下次返回值并记录每次调用
- 默认 deviceId 使用 DEVICE_RADAR_NH_KU_1
- 默认超时设置为 5ms，便于通过 QSignalSpy::wait 推进过渡态
- 每个测试用例创建独立的 controller 实例，避免状态污染

## 三、测试用例清单

### 1. 正常路径

| 编号 | 名称 | 前置状态 | 输入 | 期望状态 | 期望事件 |
| --- | --- | --- | --- | --- | --- |
| TC-01 | 初始状态为 Standby | 构造完成 | - | Standby | - |
| TC-02 | Standby 接收 work 请求 | Standby + sender ok | requestWork | Starting | sender 收到 (deviceId, 1)；workModeCommandIssued |
| TC-03 | Starting 超时进入 Working | Starting | 等待 timeout | Working | stateChanged Starting→Working |
| TC-04 | Working 接收 standby 请求 | Working + sender ok | requestStandby | Stopping | sender 收到 (deviceId, 0)；workModeCommandIssued |
| TC-05 | Stopping 超时进入 Standby | Stopping | 等待 timeout | Standby | stateChanged Stopping→Standby |

### 2. 故障路径

| 编号 | 名称 | 前置状态 | 输入 | 期望状态 | 期望事件 |
| --- | --- | --- | --- | --- | --- |
| TC-10 | Standby 发送失败进入 Fault | Standby + sender 返回 false | requestWork | Fault | stateChanged Standby→Fault；不应发出 workModeCommandIssued |
| TC-11 | Working 发送失败进入 Fault | Working + sender 返回 false | requestStandby | Fault | stateChanged Working→Fault |
| TC-12 | Fault 复位回到 Standby | Fault | reset | Standby | stateChanged Fault→Standby；sender 不被调用 |

### 3. 拒绝路径

| 编号 | 名称 | 前置状态 | 输入 | 期望状态 | 期望事件 |
| --- | --- | --- | --- | --- | --- |
| TC-20 | Standby 重复待机请求 | Standby | requestStandby | Standby（不变） | requestRejected(DuplicateRequest) |
| TC-21 | Working 重复工作请求 | Working | requestWork | Working（不变） | requestRejected(DuplicateRequest) |
| TC-22 | Starting 拒绝任何业务请求 | Starting | requestWork / requestStandby | Starting（不变） | requestRejected(TransitionInProgress) |
| TC-23 | Stopping 拒绝任何业务请求 | Stopping | requestWork / requestStandby | Stopping（不变） | requestRejected(TransitionInProgress) |
| TC-24 | Fault 拒绝业务请求 | Fault | requestWork / requestStandby | Fault（不变） | requestRejected(FaultRequiresReset) |
| TC-25 | 非 Fault 状态 reset 被拒绝 | Standby / Working | reset | 不变 | requestRejected(ResetIgnoredOutsideFault) |
| TC-26 | 过渡态 reset 被拒绝 | Starting / Stopping | reset | 不变 | requestRejected(ResetIgnoredOutsideFault) |

### 4. 事件信号

| 编号 | 名称 | 期望 |
| --- | --- | --- |
| TC-30 | stateChanged 携带正确的 old/new | 每次状态真实变化时携带正确参数 |
| TC-31 | workModeCommandIssued 携带正确 deviceId 和 mode | 仅在 sender 返回 true 时发出 |
| TC-32 | 拒绝请求不发出 stateChanged | requestRejected 与 stateChanged 互斥 |

### 5. 多设备隔离

| 编号 | 名称 | 期望 |
| --- | --- | --- |
| TC-40 | 两个不同 deviceId 的 controller 互不影响 | 操作 A 实例不影响 B 实例的状态 |

## 五、运行方式

CMake 构建后执行：

```powershell
cmake --build build --target tst_RadarWorkModeController
ctest --test-dir build --output-on-failure
```

或直接运行：

```powershell
.\build\bin\tst_RadarWorkModeController.exe
```

QtTest 会按测试用例（即 private slots 的方法名）逐项运行并打印结果。

## 六、扩展规则
