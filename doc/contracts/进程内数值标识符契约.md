# 进程内数值标识符契约

> 状态：现行规范  
> 生效日期：2026-08-31  
> 适用范围：实时进程内 `SampleMeta`、`TrackPacket`、`TrackKey` 与配置注册表边界

## 1. 目的

实时链路不在每条 Sample 中重复保存设备名、任务名、阵面名或 endpoint 字符串。组合根在配置装载、任务创建和
采集会话建立时，把外部稳定标识注册为定宽数值句柄；Producer、Topic、Consumer 和 ScratchBuffer 只传递句柄。

这些句柄具有强类型，底层位宽相同也不能互相转换。它们不是网络、数据库或录制文件格式，跨序列化边界时必须
通过对应注册表恢复外部稳定标识。

## 2. 类型与零值

| 类型              | 底层类型      | 零值           | 非零值分配者                               | 作用域             |
| --------------- | --------- | ------------ | ------------------------------------ | --------------- |
| `EndpointId`    | `quint32` | endpoint 未绑定 | EndpointRegistry                     | 当前进程配置快照        |
| `DeviceId`      | `quint32` | 设备未绑定        | DeviceRegistry                       | 当前进程配置快照        |
| `TaskId`        | `quint32` | 接收瞬间无活动任务    | TaskRegistry                         | 当前进程任务注册域       |
| `FaceId`        | `quint16` | 阵面未解析        | 设备阵面注册表                              | 与 DeviceId 组合解释 |
| `AcquisitionId` | `quint64` | 无活动采集会话      | AcquisitionRegistry/DeviceController | 当前进程采集会话注册域     |

除 `TaskId{0}` 可作为合法“无任务”业务状态外，权威航迹发布时 EndpointId、DeviceId、FaceId 和 AcquisitionId
均必须非零且能在相应注册表中解析。非零并不自动代表有效，Producer 门禁仍需检查注册表存在性和当前会话状态。

## 3. 外部稳定身份

- Endpoint 的配置键、设备台账 ID、任务业务 ID 和阵面名称只在注册表中保存一次；
- Acquisition 的外部 UUID 或数据库键由 AcquisitionRegistry 保存，TrackPacket 只携带 64 位运行时句柄；
- 配置重载、进程重启和历史回放可以重新分配数值句柄，禁止持久化后直接复用旧句柄；
- Web、数据库、日志和录制适配器必须在自己的序列化边界显式解析句柄，不得把原始数值冒充稳定业务 ID。

## 4. 类型安全与布局

五类 ID 使用 `CompactId<Tag, Storage>` 薄封装：

- 不允许从整数隐式构造；
- 不允许隐式转换回整数；
- 不同 Tag 之间不能比较、赋值或传参；
- 支持同类相等、排序和 Qt 哈希；
- 尺寸和对齐不高于底层整数；
- 保持标准布局和平凡复制，适合预分配 RingBuffer 和 ScratchBuffer。

禁止使用 `#pragma pack` 压缩这些类型，也禁止在 ID 内缓存名称、QString、注册表指针或生命周期状态。

## 5. 与后续步骤的边界

本阶段只定义 ID 值类型，不建立注册表，也不修改现有 `SampleMeta/TrackPacket/TrackKey`。下一阶段重写紧凑数据
合同时再替换原有 QString/QUuid 字段，并同步修改 Producer 门禁和测试。注册表接口必须以真实配置装载与回放需求
为输入单独设计，不得为了让 ID“看起来可用”提前增加万能字符串表。
