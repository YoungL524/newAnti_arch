# 单机一键部署契约

状态：2026-10-08 代码已实现、静态检查通过，待用户编译与运行验收；尚未生成部署 EXE 或部署包。

## 布局与生命周期

用户双击 `dcmp/NewAntiDrone.exe`，启动器独占本次启动的 Core、Web 和启用的 DP/SP；
程序目录按 `dcmp`、`dp`、`sp` 同级布局，部署根目录可移动，不写死 E 盘。
Core 与 Web 在 dcmp 工作；DP/SP 默认工作目录为 `../dp`、`../sp`。
DP/SP 的路径与参数暂不确定，默认禁用，配置后显式启用；不猜测 EXE 名称。

启动器属于进程生命周期边界，不读数据域、不发送设备 UDP Command、不创建第二命令 owner。
Windows Job Object 拥有本次进程树，进程挂起创建、纳入 Job 后才运行；控制台隐藏。
浏览器不纳入 Job，关闭页面不停止采集。重复启动不再创建进程或自动增加浏览器页面。
托盘提供打开界面与退出系统。正常退出先请求 Core 退出，由既有运行时排空归档；
随后强制结束 Web/DP/SP。Core 超过 15 秒仍未退出时记录降级并强制清理。
关闭 Job 后最多再等三秒确认受管根进程退出，超限明确报错，不冒充清理成功。
启动器异常终止时 Job Object 兜底清理；该情形不保证正常归档排空。

## Web 与终端

生产 Node 服务仅监听 `127.0.0.1`，默认端口 8080，静态网页、/api、/ws/v1、/terminal 同源。
Core 内部 HTTP 8088、WebSocket 8089、UDP 7788 保持回环和现行合同。
复用已获用户可用反馈的终端及流控；生产终端工作目录是 dcmp。
不使用 Vite dev/preview 作为生产服务器，不实现远端访问或自动重启。

## 就绪、失败和资源

Core 用当前用户可访问的本地 IPC 报告连接、就绪、启动或停机失败，接收 STOP 后调用原有 Qt 退出链。
Web 健康接口用启动期随机令牌验证实例；启动时最多一个健康请求，30 秒内必须就绪。
DP/SP 只判断进程启动成功，心跳在线仍由唯一 DeviceController 判断。
任一已启用进程启动失败或意外退出，整体有序停止并显示错误，不重试或接管已有进程。
启动诊断日志在当前用户应用数据目录，单文件上限 1 MiB 并保留一个旧文件；
子进程 stdout/stderr 重定向 NUL，Core 启动错误通过 IPC 交付，不积压不可见控制台输出。
Core 另将 Qt Warning/Critical/Fatal 写入实际数据库路径加 `.diagnostics.log` 的 UTF-8 排障文件，
当前文件及 `.1` 备份各最多 1 MiB；单行最多 8 KiB，每单调秒最多五条（Fatal 不抑制），
下一条输出携带限频抑制数。Info 接收汇总不落此文件；原控制台输出保留。
main 是唯一诊断 Owner，在运行时前安装、存储线程停止后卸载；线程内同步写，跨进程短文件锁争用时丢弃，
轮转/写失败不递归报告或排队重试。启动时文件不可写通过 IPC 报错并退出。
这是有界、尽力的低层排障文件；业务事实仍只通过 EventTopic/Web/SQLite 归档，不承诺崩溃尾部必达。
数据库沿用 Core 的应用数据路径，打包不复制或覆盖运行数据库。

## 交付与验收边界

新增一个具体部署 owner，不新增公开业务数据结构或数据转换链。
打包脚本只收集用户已编译的 EXE、UI dist、Qt DLL、固定 Node 运行时和终端运行依赖。

## 开发者生成包

新增 CMake 目标为 `NewAntiDroneLauncher`，旧 `NewAntiDrone` 仍是 Core。
两者必须来自同一个 Windows x64、Qt 5.14.2 构建。由用户完成 Release 构建和 UI 构建：

```powershell
cmake -S . -B build-release -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/mingw73_64"
cmake --build build-release --target NewAntiDrone NewAntiDroneLauncher
Push-Location ui
npm run build
Pop-Location
```

配置与构建时应使用对应 MinGW 工具环境。UI 构建前清除 `.env`/构建环境中的旧 `VITE_WS_URL`，
使生产页面使用默认同源 `/ws/v1`；地图密钥沿用用户现有构建配置。
生成包使用 PowerShell 7，在仓库根目录执行：

```powershell
./scripts/package_single_machine.ps1 -BuildDirectory ./build-release -QtBinDirectory "C:/Qt/Qt5.14.2/5.14.2/mingw73_64/bin"
```

MinGW 下从构建目录 `CMakeCache.txt` 读取编译器 bin；也可加 `-CompilerBinDirectory` 显式指定。
Qt 5.14.2 的 MinGW 插件不能可靠按调试标记筛选，打包时使用自动识别，不强制 `--release/--debug`；
MSVC 仍按 `Configuration` 指定模式。脚本检查 Windows 平台与 SQLite 插件是否进入包。
Node 默认取本机 `node.exe`，也可用 `-NodeExecutable` 显式指定；将该固定 x64 运行时一并复制，
用户电脑不需要安装 Node、Qt、npm 或编译器。
输出默认为 `release`，目录必须全新或为空；脚本只收集已有产物与 Qt 依赖，不构建或运行测试。
首次缺少编译产物时会直接失败，不生成一个伪装完成的启动包。
打包中途失败留下的目录也不能直接覆盖；保留该目录，通过 `-DestinationRoot ./release-fixed` 指定新的空目录重新收集。

```text
release/
├─ dcmp/
│  ├─ NewAntiDrone.exe           用户唯一启动入口
│  ├─ deployment.json           单机部署配置
│  ├─ Qt DLL 与 platforms/      启动器依赖
│  └─ runtime/
│     ├─ core/                  Core EXE、Qt DLL、SQLite 插件
│     ├─ node.exe               固定 Windows x64 Node 运行时
│     └─ web/                   生产入口、网页、终端与运行依赖
├─ dp/                          用户后续放置 DP
└─ sp/                          用户后续放置 SP
```

部署时可将这三个目录放到 E 盘对应位置。不能只复制启动 EXE，`dcmp` 内运行文件须一起交付。
DP/SP 后续在 `dcmp/deployment.json` 中填写实际 EXE 路径和参数，并将 `enabled` 改为 true。
相对路径统一以 dcmp 为基准，例如实际 DP EXE 位于同级 dp 目录时使用 `../dp/实际文件名.exe`；
`workingDirectory` 保持 `../dp`/`../sp`，不受用户双击时的当前目录影响。
DP/SP 禁用时 Core/Web 仍可启动，真实心跳离线由原业务链呈现，不伪造在线状态。

## 用户验收

离线底图已接入，取代下节“地图断网仍不可用”的阶段性描述；详见 `Web离线地图契约.md`。

### 离线部署第 1、2 阶段（2026-10-12，待用户构建验收）

Core 已修正初始 v4 建表提前创建 archived_utc_ms、v11→v12 再次添加的重复列错误；
正常旧库仍补列，旧错误初始化已经含列时保留已有值后继续升级，不删除数据库。
Core 航迹与心跳端点保持 127.0.0.1:7788，DP/SP 自动拉起保持禁用。

UI 的 Inter、JetBrains Mono 与 Material Symbols 改为仓库内本地字体；字形由 Vite 打包，
许可证位于 dist/third-party-fonts。生产服务器支持 TTF/WOFF2 MIME。无额外 npm 字体依赖或运行期下载。
高德地图仍需要公网；本阶段不包含独立雷达画布，断网时地图区域仍不可用。

打包脚本在创建输出前比较 Core、启动器、UI 产物与对应源码目录的修改时间，拒绝明显旧产物。
此检查不能证明构建成功或依赖完整；打包完成另生成 package-manifest.json，
包含收集时间、配置和程序/网页 SHA256。清单不含数据库、deployment.json 或用户 DP/SP 文件，
后续手动替换程序或网页后须重新生成包，不能沿用旧清单声称版本一致。

用户构建完成后，可更新当前 release-fixed；先从托盘退出，执行：

```powershell
cmake --build ./build-release --target NewAntiDrone NewAntiDroneLauncher
Push-Location ui
npm run build
Pop-Location
Copy-Item ./build-release/core/NewAntiDrone.exe ./release-fixed/dcmp/runtime/core/NewAntiDroneCore.exe -Force
Copy-Item ./build-release/deployment/NewAntiDroneLauncher.exe ./release-fixed/dcmp/NewAntiDrone.exe -Force
Copy-Item ./ui/dist/* ./release-fixed/dcmp/runtime/web/dist/ -Recurse -Force
Copy-Item ./ui/server/production.mjs ./release-fixed/dcmp/runtime/web/server/production.mjs -Force
Copy-Item ./ui/server/offline-map.mjs ./release-fixed/dcmp/runtime/web/server/offline-map.mjs -Force
New-Item -ItemType Directory ./release-fixed/dcmp/runtime/web/maps -Force
Copy-Item ./ui/maps/basemap.mbtiles ./release-fixed/dcmp/runtime/web/maps/basemap.mbtiles -Force
```

上述更新保留现场配置、DP/SP 和数据库；旧哈希资源文件可能留在 dist，入口仅引用本次构建资源。
完整交付优先使用前述打包脚本输出到新的空目录，生成清单并保留现有 release-fixed 作为回退包；
DP/SP 仍由现场手动启动，不将默认禁用配置改成自动联启。

离线验收由用户执行：

1. 先备份数据库，在全新应用数据环境验初始化；再用原故障库副本验升级，确认没有重复列错误、原任务与设备保留。

1. 在没有开发环境的 Windows x64 电脑上双击 dcmp 的启动 EXE，确认只打开一个 Web、没有控制台。

8. 检查数据库继续使用应用数据目录；更换程序包不覆盖历史任务、航迹或设备台账。
