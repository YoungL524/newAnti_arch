# Web 本机交互终端契约

状态：2026-10-05 实现，用户已反馈开发版非常好用；2026-10-08 增加生产入口复用，部署版待用户验证。

## 范围与唯一 owner

运行 Web 服务的 Windows 电脑提供 PowerShell/CMD 交互终端，初始目录为本仓库根目录。
终端使用当前启动 Web 服务的 Windows 用户权限。它属于本机运维入口，不属于设备 Command 或雷达数据平面。

```text
TerminalPanel / xterm.js
  <-> 同源 WebSocket /terminal/ws
  <-> Vite Node 进程中的单会话服务
  <-> node-pty / Windows ConPTY
  <-> PowerShell 或 CMD
```

`ui/terminal/server.mjs` 唯一拥有 PTY 与连接，开发 Vite 和生产 Web 入口调用同一实现；`TerminalPanel.tsx` 唯一拥有浏览器终端。
不进入 CoreDataDomain，不新增日志 Topic、归档路径、设备命令 owner 或 Qt 线程。
同一 Web 服务最多一个终端会话；第二个页面不能接管或旁观已有会话。

## 启动与页面入口

依赖已锁定为 `@xterm/xterm 6.0.0`、`@xterm/addon-fit 0.11.0`、`node-pty 1.1.0`、`ws 8.22.0`。
需要支持 ConPTY 的 Windows 10/11（build 至少 18309）与本机 Node.js 环境。
本次安装使用 `--ignore-scripts`，Windows x64 原生文件已随 npm 包提供，代理未编译依赖或项目。

开发使用既有入口：

```powershell
cd D:\NewAntiDrone-newArch\newAnti_arch\ui
npm run dev
```

在该电脑浏览器打开 `http://localhost:5173`（端口占用时以 Vite 实际输出为准），选择底部“终端”。
首次进入自动连接 PowerShell；点击“断开”后可以选择 CMD 再连接。
“放大/还原”、切换页签、折叠面板保留会话；关闭页面、刷新、断开连接或结束 Web 服务会终止会话。
服务启动时创建认证令牌，不自动重连、不重放输入。

生产预览由用户先完成 `npm run build`，再用 `npm run preview` 打开 Vite 输出的本机地址。
dev/preview 均由同一插件挂接终端路由；静态文件服务器单独托管 `dist` 不提供终端后端。
终端位于 Node Web 服务所在电脑，Qt 主程序不负责启动它。
正式单机部署由启动 EXE 自动管理生产 Web 服务，终端初始目录为 dcmp，无需运行 npm；详见 `单机部署契约.md`。

## 输入、输出与资源边界

- 输入保留终端按键序列，支持方向键、Tab、Ctrl+C、交互程序和粘贴；UTF-16 分块不拆代理对。
- UTF-8 输出使用二进制帧，每帧最多 32 KiB，xterm.js 自行处理跨帧多字节字符和 ANSI 序列。
- 输出正文不进入 React state；终端按需加载，日志更新不触发终端组件渲染。
- xterm.js 解析回调确认消费字节，服务器未确认输出达到 256 KiB 暂停 PTY 读取，回落到 64 KiB 恢复。
- 未确认输出与待发送缓冲合计超过 1 MiB 时明确结束会话，不静默丢字符；回滚屏幕保留 3000 行。
- 控制消息上限 64 KiB，单输入块最多 16 KiB UTF-8，屏幕列数 2～500、行数 2～200。
- 尺寸观察按浏览器帧合并；隐藏不传零尺寸，重新显示时恢复与当前容器一致的几何。
- Shell 自然退出后等待已产生输出排空再报告退出码，最多等待五秒；断开主动销毁伪终端。
- 正常控制台进程由 node-pty 清理；Shell 主动脱离控制台启动的独立服务不属于会话资源。

## 访问与失败合同

只接受回环 TCP 客户端，Host 必须为 localhost/127.0.0.1/IPv6 回环且端口匹配实际监听端口。
WebSocket Origin 必须与当前入口同源；HTTP 令牌接口校验本机来源、浏览器跨站标记及专用请求头。
令牌经同源 fetch 取得，在首条 WebSocket 消息认证，不放入 URL，不允许跨域读取或缓存。
匿名连接五秒内未认证关闭；认证失败、原生模块加载失败、Shell 启动失败、非法消息和输出积压均结束当前会话。
终端访问失败不停止地图或 Qt 雷达后端，也不冒充设备确认。

## 用户运行验收

1. 打开终端，执行 `Get-Location`，确认位于仓库根目录；输入中文并检查显示。
2. 在 PowerShell 逐项检查方向键历史、Tab 补全、Ctrl+C 中断、复制选区和粘贴。
3. 执行 `1..10000 | ForEach-Object { "终端输出 $_" }`，检查无逐字符卡顿、结尾出现 10000 且提示符恢复。
   初始屏幕与回滚只保留配置的行数；不要求保存全部输出历史。
4. 在一个持续输出命令期间切换活动日志、折叠、放大与还原，再返回终端，检查会话仍在、提示符与光标位置正常。
5. 执行 `exit`，确认尾部输出完整并显示退出码；切换 CMD 连接，执行 `dir` 和 `chcp`。
6. 第二个浏览器页面尝试连接，应明确失败；关闭第一个会话后第二个页面可手动连接。
7. 在普通控制台子进程运行时点击断开或关闭页面，检查该会话进程退出；地图和核心采集保持正常。
8. 同时进行模拟航迹显示与终端连续输出，检查输入响应、地图更新和资源占用，再报告是否达到实际使用要求。

开发终端已有用户可用反馈；上述逐项及生产部署版仍需用户验收，不是代理运行结果。
代理仅执行注释审计、语法和不产物的静态类型检查。

实现依据：[xterm.js 流控](https://xtermjs.org/docs/guides/flowcontrol/)、
[node-pty 原生伪终端](https://github.com/microsoft/node-pty)。
