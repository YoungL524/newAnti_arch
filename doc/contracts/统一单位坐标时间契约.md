# 统一单位、坐标与时间契约

> 状态：现行规范
> 版本：1.1
> 生效日期：2026-08-26
> 适用范围：新架构进程内业务模型、协议适配器、显示投影、存储映射和对外 DTO

## 1. 目的与约束等级

本合同消除“字段名相同但单位、方向或时间基准不同”的隐式约定。所有 Producer 必须在数据进入 `CoreDataDomain` 前完成单位、轴向、符号和时间基准标准化；Consumer 不得根据厂家、端点或页面再次猜测。

本文中的“必须”“不得”是代码审查和验收门禁；“建议”允许在有记录的 ADR 中调整。

边界分工：

```text
厂家协议 / 配置 DTO / 文件 / 网络
  -> ProtocolAdapter 或 BoundaryMapper 完成显式转换
  -> 进程内统一模型
  -> Display / Storage / Web / Plugin 主动读取
  -> 各自边界 DTO 按协议要求再次显式转换
```

禁止在业务处理中出现没有字段后缀、注释或合同支持的“乘 1000”“除 57.3”“补负号”“加航向”等隐式换算。

## 2. 命名与数值表示

### 2.1 字段后缀

| 物理量 | 进程内标准 | 字段后缀示例 |
| --- | --- | --- |
| 长度、距离、高度 | 米 | `lengthM`、`distanceM`、`heightM` |
| 速度 | 米/秒 | `radialVelocityMps`、`vxMps` |
| 核心算法角度 | 弧度 | `azimuthRad`、`elevationRad` |
| 人工配置和 Web 表单角度 | 度 | `longitudeDeg`、`absoluteHeadingDeg` |
| UTC 墙上时间 | Unix epoch 毫秒 | `receiveTimeUtcMs` |
| 进程内单调时间 | 纳秒 | `receiveTimeSteadyNs` |
| 频率 | 赫兹 | `frequencyHz` |
| 时长 | 毫秒或纳秒，按用途显式命名 | `timeoutMs`、`latencyNs` |

无单位后缀的字段仅允许用于无量纲值、枚举、ID、计数和已有外部协议 DTO；协议 DTO 必须在其适配器旁注明厂家单位。

### 2.2 浮点和缺失值
- 连续物理量使用 `double`；第一版不以节省少量内存为由降为 `float`。
- 所有进入权威 Topic 的必填物理量必须是有限数，禁止 `NaN`、正负无穷。
- `0` 是合法数值，不得兼任“未知”“未提供”哨兵。
- 可缺失物理量使用 `std::optional<T>`；缺失和测得零值必须可区分。
- 适配器不能确认单位、方向或基准时不得猜测；应保持字段为空，并按重要性发布 Warning/Error `SystemEvent`。
- 超出合同范围的必填值不得发布到权威 Topic；原始报文可按独立采集策略留档用于诊断。

## 3. 坐标系

### 3.1 地理坐标

设备安装位置和对外地理位置的水平基准统一采用 WGS-84；垂直量统一采用设备 GPS 输出的平均海平面海拔高度。由于 EPSG:4979 的第三维是椭球高，本文的三字段组合不得标记为 EPSG:4979：

| 字段 | 定义 | 合法范围 |
| --- | --- | --- |
| `longitudeDeg` | 东经为正的经度，单位度 | `[-180, 180]` |
| `latitudeDeg` | 北纬为正的纬度，单位度 | `[-90, 90]` |
| `altitudeM` | 相对平均海平面（MSL）的海拔高度，单位米；不是 WGS-84 椭球高 | 有限数 |

设备配置、数据库和界面不得把 `altitudeM` 重命名或解释为椭球高。需要执行高精度 WGS-84 ECEF/ENU 变换时，测地转换边界必须使用已配置且可追溯的大地水准面模型，将海拔高度显式转换为椭球高；缺少该模型时只能进行标明精度限制的短距离显示计算，不得用于跨设备融合或验收基准。旧版 `111320 m/degree` 平面近似只可作为短距离 UI 预览。

### 3.2 雷达局部坐标 RFU

每个雷达阵面使用右手局部坐标系 RFU：

- `+X`：阵面右方（Right）；
- `+Y`：阵面正前方/波束中心方向（Forward）；
- `+Z`：阵面上方（Up）；
- 原点：配置中定义的雷达测量参考点，不默认等于机柜、天线底座或 GPS 天线位置。

局部位置字段统一为 `xM/yM/zM`，局部速度字段统一为 `vxMps/vyMps/vzMps`。厂家使用 NED、ENU、FRD 或其他轴序时，协议适配器必须在进入核心模型前完成轴交换和符号转换。

### 3.3 局部极坐标
`TrackPacket` 极坐标以同一 RFU 坐标系定义：

- `rangeM`：雷达参考点到目标的斜距，必须 `>= 0`；
- `azimuthRad`：相对当前 DeviceId 阵面法线，从 `+Y` 向 `+X` 为正；当前单面阵合同范围 `[-π/4, π/4]`；
- `elevationRad`：从局部水平面向 `+Z` 为正；当前雷达合同范围 `[0, π/4]`。

两种表示的数学关系为：

```text
horizontal = distanceM * cos(elevationRad)
xM = horizontal * sin(azimuthRad)
yM = horizontal * cos(azimuthRad)
zM = distanceM * sin(elevationRad)
```

极坐标是第一版 `TrackPacket` 的权威位置表示。厂家同时提供笛卡尔位置时，可作为可选辅助测量保留，但适配器必须检查二者一致性；Consumer 不得自行选择不同“真值”。

### 3.4 世界局部坐标 ENU

以设备 WGS-84 安装点为原点建立 ENU：

- `+E`：正东；
- `+N`：正北；
- `+U`：沿 WGS-84 椭球法线向上。

RFU 经安装姿态旋转后得到 ENU，再通过 WGS-84 ENU/ECEF 变换得到目标地理位置。TrackPacket 不重复持久保存由姿态和局部位置可确定的世界坐标，避免设备配置变化后出现两套互相矛盾的位置。

## 4. 雷达 6DOF 姿态

### 4.1 位置三自由度

设备位置由 `longitudeDeg`、`latitudeDeg`、`altitudeM` 组成，参考点必须与 RFU 原点一致；若 GPS 天线存在杆臂偏移，应在配置导入或标定层修正。

### 4.2 绝对航向、俯仰和横滚
| 字段 | 定义 | 正方向 | 标准范围 |
| --- | --- | --- | --- |
| `absoluteHeadingDeg` | 阵面 `+Y` 相对真北的绝对航向；它就是 Yaw | 从真北向东顺时针 | `[0, 360)` |
| `pitchDeg` | 阵面正前方相对局部水平面的俯仰 | 抬头为正 | `[-90, 90]` |
| `rollDeg` | 阵面绕 `+Y` 轴的横滚 | 右侧下沉为正 | `[-180, 180)` |

强制规则：
1. 航向基准是真北，不是磁北、地图网格北或设备启动时的相对零位。
2. `absoluteHeadingDeg` 是雷达安装后测得的最终绝对朝向，从接入到显示不得再次与 `Yaw`、`boresightAzimuth`、安装偏移或其他朝向相加。
3. 配置界面中的阵面“绝对朝向”是唯一 Yaw 来源；位置/姿态区域不得再保存第二个 Yaw。
4. 当前一个 `DeviceId` 就表示一个雷达阵面并拥有唯一 `absoluteHeadingDeg/pitchDeg/rollDeg`；未来四面阵按阵面注册四个 DeviceId，物理机箱归组不进入 TrackPacket。
5. 旧字段 `mountOffsetAzimuth` 只用于历史兼容，禁止参与新架构坐标变换。

### 4.3 旋转顺序

RFU 到 ENU 的固定顺序为：
1. 在 RFU 中绕 `+Y` 应用 roll；
2. 绕更新后的 `+X` 应用 pitch；
3. 以真北为零、顺时针应用阵面绝对 heading，映射到 ENU。

在 roll/pitch 均为零时，heading 变换必须满足：

```text
eastM  = xM * cos(heading) + yM * sin(heading)
northM = -xM * sin(heading) + yM * cos(heading)
upM    = zM
```

验收基准：heading=0° 时阵面正前方指向北；heading=90° 时阵面正前方指向东；任何实现都不得通过“航向 + 阵面方位”得到结果。

## 5. 速度与雷达量

- `radialVelocityMps` 遵循当前雷达业务协议：抵近雷达为正，远离雷达为负；它不是数学符号下的 `d(rangeM)/dt`。
- 协议适配器必须保留该符号约定，Consumer 不得再次取反。
- `vxMps/vyMps/vzMps` 与 RFU 的 `+X/+Y/+Z` 同向；厂家轴系不同必须先变换。
- `amplitude` 保存厂家提供的 double 幅值原值；当前只要求有限，不换算为 RCS 或 dBsm，也不假设物理单位。

## 6. 时间模型

### 6.1 三类时间

| 字段 | 类型与单位 | 写入者 | 用途 | 是否持久化 |
| --- | --- | --- | --- | --- |
| `sourceTimeUtcMs` | `qint64` + validity，Unix epoch ms | ProtocolAdapter | 已同步设备给出的测量时间 | 标志有效时保存 |
| `receiveTimeUtcMs` | `qint64`，Unix epoch ms | 通信入口 | 业务查询、日志、Web 时间和跨进程关联 | 必须 |
| `receiveTimeSteadyNs` | `qint64`，单调 ns | 通信入口 | 进程内时延、超时、陈旧判断 | 不作为业务时间持久化 |
| publish latency 指标 | 聚合值，单调 ns | Producer/metrics | 接入至发布时延、Reader lag | 不随每条 Sample 保存 |

第一版使用 `std::chrono::system_clock` 获取 UTC、使用 `std::chrono::steady_clock` 获取单调时间。封装层应集中完成到整数单位的转换，不允许各模块采用不同 epoch 或精度。

### 6.2 时间规则

1. UDP 完整报文从 socket 取出后立即、且只采集一次 receive UTC 与 steady 时间；同一报文解出的所有航迹共享该接收时刻。
2. 设备没有时间或没有完成 UTC 同步时，清除 `HasSourceTimeUtcMs` 且数值置零；不得把接收时间复制进去伪装成设备时间。
3. UTC 可以因校时向前或向后跳变，不得用于超时、耗时、队列滞后和 50 ms 周期判断。
4. steady 时间的 epoch 只在本进程有效，不得写入对外协议充当绝对时间，也不得跨重启比较。
5. Producer 可在调用 publish 前即时计算 `nowSteadyNs - receiveTimeSteadyNs` 并写入聚合指标，禁止把该时间再次塞回每条 Sample。
6. 默认业务展示时间优先使用标志有效的 `sourceTimeUtcMs`，否则明确回退到 `receiveTimeUtcMs`；DTO 应能说明选择来源。
7. 数据库和 JSON 使用整数毫秒，不使用本地时区字符串；界面展示时才根据用户时区格式化。

## 7. 序号和身份不得混用

| 名称 | 所有者 | 作用域 | 可否持久化为业务主键 |
| --- | --- | --- | --- |
| `sourceSequence` | 设备/厂家协议 | 厂家定义的连接、扫描或设备周期 | 否，只用于源侧缺口诊断 |
| `topicSequence` | 单个 `HistoryTopic<T>` | 当前进程内单 Topic | 否，只用于 Reader cursor |
| `traceId` | 当前进程入口 | 一次接收/处理链 | 否，只用于诊断关联 |
| `trackId` | 雷达设备 | 单设备采集会话 | 不能单独作为全局主键 |
| `acquisitionId` | 上位机控制平面 | 一次开始接收到停止/断线终止 | 是 TrackKey 的组成部分 |

`topicSequence` 不进入业务载荷；`sourceSequence` 不得用于 RingBuffer 定位；UTC 时间也不得充当唯一航迹身份。

## 8. 边界转换责任

### ProtocolAdapter

- 校验包头、命令字、声明长度、包尾和 CRC；
- 将厂家长度、速度、角度、轴向和正负方向转换为本文标准；
- 只有在厂家时间基准和同步状态明确时填写 `sourceTimeUtcMs`；
- 不能确认语义的可选字段保持为空；必填字段不能确认时拒绝发布并产生 `SystemEvent`。

### WebReader / Web

- 从 RFU、设备 6DOF 和 WGS-84 安装点派生 ENU/地理显示坐标；
- 只在 JSON/UI 边界把弧度转换为度；
- 不修改权威 TrackPacket，不缓存第二套“修正后航向”。

### StorageReader

- 列名必须包含单位后缀；
- UTC 毫秒用于查询索引，steady 时间只用于聚合时延指标；
- `optional` 缺失保存为 SQL `NULL`，不得保存为零。

### Plugin / External Adapter

- 插件内部读取统一模型；
- 第三方协议要求不同单位或坐标系时由各自输出适配器转换；
- 不得为迁就单一插件改变核心模型单位。

## 9. 最低验收矩阵

- heading=0°、局部 `(x=0,y=100,z=0)` 必须得到北向 100 m；
- heading=90°、同一点必须得到东向 100 m；
- azimuth=-45°、0°、+45° 必须通过门禁，超出边界必须拒绝；
- elevation=0°、45° 必须通过门禁，负值或大于 45° 必须拒绝；
- 厂家抵近目标 `+10 m/s` 必须原样保留为 `+10 m/s`，远离目标必须为负；
- 幅值必须保留厂家 double 原值，`NaN/Inf` 必须拒绝，不进行 dBsm 换算；
- 设备无同步时间时 source time 必须为空而 receive time 有值；
- UTC 回拨不得导致 Topic sequence、超时或 latency 出现倒序；
- DeviceId 无法解析唯一安装姿态时必须在 Producer 上游拒绝，不能按 0°显示；
- 任意必填浮点为 `NaN/Inf` 时必须拒绝发布并记录事件。
