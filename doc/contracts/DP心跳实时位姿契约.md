# DP 心跳实时位姿契约

> 2026-09-30 确认：DP 按阵面分别发送经纬高与三轴姿态；DCMP 对在线阵面的经纬高分别求平均作为雷达位置，姿态保持逐面独立。心跳值仅用于实时显示，不随心跳写入 SQLite 设备台账。

## 线协议

`0x0101` 使用 44 字节公共头、104 字节载荷、4 字节公共尾，完整包为 152 字节，公共头声明长度为 140。载荷均为小端；前 4 字节保持 `dpOnline:uint16` 和 `fpOnlineMask:uint16`。位图 bit0～3 对应 1#～4# FP 在线，不能作为单一阵面索引，也不能当作设备 ACK。

| 载荷偏移 | 字段 | 格式 |
| --- | --- | --- |
| 4～99 | `facePose[4][6]` | 按 1#～4# 顺序，每面 24 字节；依次为经度 1e-6°、纬度 1e-6°、MSL 海拔 cm、航向/俯仰/横滚 0.01°，均为 `int32` |
| 100 | `poseFormatTag` | `uint32`，固定 `0x32534F50`，小端字节为 `POS2` |

仅当 `poseFormatTag=POS2`、DP 在线且某阵面的 `fpOnlineMask` 位为 1 时，该面的六个值有效。DCMP 对所有在线面分别计算经度、纬度、海拔的算术平均，结果按协议整数单位四舍五入；不平均三轴姿态，不使用离线面的数值。旧版 132 字节 DP 心跳只更新在线状态，不将其 POS1 位姿误解为 POS2；离线位的六个值不校验，也不更新实时显示。经度限于 ±180°、纬度限于 ±90°、海拔限于 -1000～10000 m、航向限于 ±180°、俯仰与横滚限于 ±90°；在线面超范围时丢弃整包，保持前一份有效状态。航向的负角度由界面换算为 0～360°显示。DP 主动离线或 2 秒迟到时清除实时有效位，界面回退设备台账值。

## 运行态与界面

`DcmpProtocolAdapter` 逐字段解码后交给唯一 `DeviceController`，由其求平均并将结果写入 `LatestState<DeviceState>`；该状态只保留平均雷达位置、逐面姿态及有效阵面位，不长期保存四套原始坐标。`StateWebSocketService` 只发布与当前准备任务设备绑定的实时位姿；UI 使用该设备 ID 覆盖部署页、地图雷达位置和阵面姿态的显示值。台账原值仍供无实时位姿时回退，保存按钮不把心跳值写入 SQLite。SP 心跳继续使用原有 132 字节布局。
