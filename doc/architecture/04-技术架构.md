## 4. 线程模型

| 线程 | 职责 |
| --- | --- |
| Qt 主线程 | QObject、UDP、HTTP、WS、业务服务、定时器 |
| SystemBus worker | 从队列取事件并分发订阅者 |
| StdinReader | 阻塞读取控制台输入 |

原则：

- 业务 QObject 尽量留在主线程；
- 跨线程回调使用 queued connection；
- 不在 Web/UI 层直接访问通信对象。

当前 SystemBus worker 会顺序调用命中的订阅回调，因此总线本身不等于自动并行。目标规则是：总线回调只做快速投递，识别、转发和存储等模块在各自执行上下文中处理；是否增加线程由实测负载决定，不采用“每个类一个线程”。

## 6. 技术边界

```text
厂家协议变化:
  新增或替换 input/output adapter / config

识别算法变化:
  替换 RecognitionModule，不修改显示、转发和 Web

Web UI 变化:
  修改 ui 和 core-web DTO adapter

业务规则变化:
  修改业务服务层

部署或端口变化:
  修改 config / 启动参数
```

技术架构目标是让这些变化互相隔离。

## 7. SystemBus 载荷使用约定

SystemBus 只发布一种顶层消息 `DataPacket`，订阅回调统一为：

```cpp
void(const DataPacket* packet)
```

`DataPacket::command` 是命令字，`DataPacket::payload` 是 `std::variant` 类型安全载荷。固定协议值直接存入 variant；显示快照等复杂对象使用 variant 中声明的 `shared_ptr<const T>` 分支。

固定规则：

- 不使用固定 `rawData[4096]`；
- 不使用 `shared_ptr<const void>`；
- 不再增加第二套 Envelope 发布/订阅接口；
- 命令字和实际 variant 类型必须同时匹配；
- 厂家 `GeneralPackage` 命令只作为迁移兼容项，标准航迹接通后删除；
- 正式航迹使用 `DataCommand::Track + shared_ptr<const TrackPacket>`。

当前链路与迁移状态见 `doc/architecture/08-现有航迹链路审计与统一入口.md`。

## 8. 模块与 DLL 边界

当前阶段采用同一进程、编译期注册和配置启停。识别、显示、转发、引导、存储及性能统计按接口隔离，但暂不承诺二进制插件 ABI。

接口稳定后可评估 Qt Plugin 或稳定 C ABI DLL。插件必须只依赖版本化标准消息和生命周期接口，不能直接访问 `AppController`、其他模块成员或厂家无关的数据库实现。
