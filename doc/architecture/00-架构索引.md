## 业务与技术摘要

系统负责设备配置、单活动任务、多设备采集、航迹显示、事件记录、归档及后续转发；
雷达航迹起批与融合属于 DP。显示只有 React Web，不建设 Qt 地图。
配置由数据库及正式 owner 管理，Web 不直接修改协议对象。

后端为 Qt 5.14.2 / C++17 / CMake，前端为 React / TypeScript / Vite，持久化采用 SQLite。
HTTP/WebSocket 服务端口由配置决定（现有约定 8088/8089）；设备端点按配置绑定。
Web 复用事件循环，归档使用共享存储 Lane，插件执行资源按需启用；不要求一消费者一线程。

主链为 Producer → 共享 Topic ← Reader；Reader 使用 cursor 和固定 ScratchBuffer，
ExecutionLane 合并 Doorbell。控制经 ApplicationController → DeviceController → DcmpProtocolAdapter → 本地 UDP Socket 单向发送；没有设备 ACK 或周期命令 FIFO。
具体并发、覆盖和失败规则只维护在 09 与 AGENTS.md，不在本页重复定义。

## 当前协议边界

公共头 44 字节、包尾 4 字节；声明长度为 36+N，实际长度为 48+N，版本为 20260915。
已定义控制 0x0001、DP 返回 0x0100 的状态及航迹点、DP 心跳 0x0101、SP 心跳 0x0303。
心跳载荷84字节；0x0100载荷608字节，含384字节状态和224字节航迹点；不能直接拿内部 TrackPacket 当网络载荷。

协议类型已经实现不等于设备 Adapter、状态 owner 和 Command 联调完成。
DP/SP 主动每秒发送心跳，5秒未收到判离线；DP/SP 没有命令 ACK，具体实现不得从旧 DPH 推断确认流程。
