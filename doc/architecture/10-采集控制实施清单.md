# 采集控制实施清单

> 状态：V1 业务边界已冻结；后续严格按本清单一次完成一步，完成验收后停下，再由用户安排下一步。

## 1. 权威边界

本文件只规定采集与控制的业务顺序；进程内数据流、线程和所有权仍以
`09-共享强类型数据域与游标读取模型.md`、`新架构4.png` 和根目录 `AGENTS.md` 为准。
线协议字段以[2026-09-23 应用版 Excel](../protocol/★数据协议(四面阵雷达)_应用版（1.0）_20260923.xlsx)、`core/protocol` 及 `doc/protocol/toDP.h` 为准。

冻结规则如下：

1. “开始采集”的核心效果是本地任务进入采集状态并让 PPI 开始扫描；系统不存在“联机/演示”两套模式。
2. DCMP 与 DP/SP 之间没有 ACK 或握手。UDP 数据报交给本地 Socket 发送成功，只表示本机受理，不表示 DP、SP 或 FP 已执行。
3. 本地采集开始/停止成功后，分别向 `127.0.0.1:1234` 发送一次 `0xFFFF` 工作/待机命令，值为 1/0；`0x0001` 整包周期链独立运行，字段联动另议。
4. 当前任务激活后，DP、SP 心跳共同门控 50 ms `DcmpToDpControlPayload` 周期发送：二者均在线才发送；任一离线或任务完成立即停止，恢复双心跳后自动续发。
5. 心跳变化不得停止本地 PPI、结束任务或销毁采集会话；心跳是可观测运行状态，不是本地扫描状态机的确认信号。
6. `DcmpToDpControlPayload` 的 `CommonControl`、`FrameControl`、`Navigation` 各只有一份；仅 `FaceControl[4]` 按阵面独立。
7. 50 ms 参数控制发送读取 Owner 持有的最新快照，不把每个周期压入 per-device FIFO；`0xFFFF` 只在本地状态成功切换后一次性发送，不建 FIFO、ACK 或重试。
8. 航迹只允许 `UDP -> DcmpProtocolAdapter -> TrackIngressProducer -> TrackTopic <- Web/Archive Consumer` 一条正式链路。

## 3. 采集工作控制决定

已登记独立 `0xFFFF` 命令字：本地开始采集成功后发 1，停止成功后发 0，目标固定为 `127.0.0.1:1234`；本地切换不依赖 UDP 提交结果。`0x0001` 在任务激活且双心跳在线期间持续发送，采集停止后也继续；任务完成或心跳掉线才停发。该 UDP 结果不作为本地PPI或任务状态的ACK。
