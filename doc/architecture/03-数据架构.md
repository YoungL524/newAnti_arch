# 03 - 数据架构

> 数据架构描述系统有哪些核心数据、谁拥有它们、如何流转和持久化。  
> 它不关心具体 UI 组件，也不展开类依赖。

## 2. 数据所有权

| 数据 | 所有者 | 说明 |
| --- | --- | --- |
| `EndpointConfig` | 通信配置 | 描述如何收发数据 |
| `DeviceInfo` | 后端设备台账 | 描述业务设备 |
| `DeviceEndpointBinding` | 后端设备台账 | 连接业务设备和通信端点 |
| `TaskInfo` | 后端任务服务 | 描述任务生命周期 |
| `RuntimeSettingsSnapshot` | 后端运行时参数服务 | 当前有效运行参数 |
| `Raw Protocol Data` | 协议适配层 | 厂家协议，不出 core |
| `NormalizedTrackBatch` | 输入协议适配层 | 已完成协议、单位和字段标准化，尚未识别 |
| `IdentifiedTrackBatch` | 识别服务 | 显示、转发、引导和存储共同消费的权威航迹 |
| `TrackDisplaySnapshot` | 航迹显示管理 | 给 Web 的固定显示数据 |
| `ExternalTrackFrame` | 输出协议适配层 | 面向某个第三方的编码结果，不进入通用业务模块 |
| `SystemEvent` | 日志/事件服务 | 系统事件、告警、错误 |
| `OperationLog` | 任务/事件服务 | 用户操作记录 |

## 3. 设备数据

设备数据分两层：

```text
EndpointConfig:
  id
  protocol
  localAddress
  localPort
  targets

DeviceInfo:
  deviceId
  name
  type
  vendor
  model
  location
  faces
  endpointBinding
```

结论：

- 端点是通信对象；
- 设备是业务对象；
- 不要把所有设备信息塞进 `endpoints.json`。

## 4. 运行时参数数据

```text
RuntimeSettingsSnapshot:
  version
  updatedAt
  updatedBy
  deviceId
  dphParams
  radarFaces
  workModeIntent
```

规则：

- 当前代码要求 UI 提交完整运行时参数 DTO；
- 后端持有当前有效快照；
- DPH 使用当前有效快照组包；
- 需要记录版本和更新时间；
- 局部更新可以作为后续扩展，但不能和当前 API 契约混写。

## 5. 航迹数据

```text
Raw Protocol Data
  -> NormalizedTrackBatch
  -> IdentifiedTrackBatch
       -> TrackDisplaySnapshot
       -> ExternalTrackFrame
```

`NormalizedTrack` 建议字段：

```text
trackId
deviceId
timestamp
range
azimuth
elevation
x/y/z
velocity
rawSource
```

`IdentifiedTrack` 在标准航迹字段上增加：

```text
identity/type
confidence
recognitionSource
recognitionVersion
```

`TrackDisplaySnapshot` 建议字段：

```text
trackId
deviceId
taskId
timestamp
position/polar
display: color/size/shape/opacity/trail/highlight
interaction: selected/trackingEnabled
routing: optional flags
```

结论：

- 上位机不负责航迹生命周期算法；
- 目标识别是标准航迹成为正式业务输出前的必经步骤；
- 上位机负责航迹显示状态和识别后数据的对外输出；
- Web 只依赖 `TrackDisplaySnapshot`。

历史存储默认保存 `IdentifiedTrackBatch` 对应的标准字段和识别结果。是否同时保存厂家原始帧由独立采集策略决定，不能让原始帧成为历史查询的唯一依据。

## 6. 固定 Core-Web 数据协议

建议固定这些 DTO：

```text
DeviceInfo
DeviceRuntimeState
TaskInfo
RuntimeSettingsSnapshot
TrackDisplaySnapshot
SystemEvent
CommandResult
```

这是 Core 与 React 前端稳定协作的基础。

第三方协议不复用 Web DTO。第三方输出统一从 `IdentifiedTrackBatch` 生成，由各自 `OutputProtocolAdapter` 负责编码。
