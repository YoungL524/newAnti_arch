# 1. 通用报文封装

## 1.1 编码规则

- 一个 UDP 数据报承载一个完整报文，不允许跨数据报拼接。
- 多字节整数和 IEEE 754 浮点数使用小端字节序。
- 基础字段均为 4 字节自然对齐；线上数据按表格顺序逐字段编码，不直接依赖编译器结构体内存布局。
- 数据域长度 `N` 必须为 4 的倍数；补齐字节和备份字段发送时必须置零。
- `messageType` 只确定数据域结构，不作为 DCMP 进程内业务分发标识。

## 1.2 公共头和包尾

公共头固定 44 字节，随后为 `N` 字节数据域，最后为 4 字节包尾。完整 UDP 数据报长度为 `48+N`。
`F_UI_TotalLength` 的值为 `36+N`，不包含包头标志、长度字段自身和包尾。


| 偏移 | 字节 | 字段                    | 类型     | 定义                                  |
| ---: | ---: | ----------------------- | -------- | ------------------------------------- |
|    0 |    4 | `F_UI_Package_Head`     | uint32   | 包头标志，固定为`0xA1A11A1A`          |
|    4 |    4 | `F_UI_TotalLength`      | uint32   | 声明长度，固定部分 36 字节，即`36+N`  |
|    8 |    4 | `F_UI_MessageType`      | uint32   | 消息类型，决定数据域结构              |
|   12 |    4 | `F_UI_Protocol_Version` | uint32   | 协议版本，固定为`20260915`            |
|   16 |    4 | `F_UI_GPS_Time_DMY`     | uint32   | GPS／外部日期，具体位编码按协议表     |
|   20 |    4 | `F_UI_GPS_Time_SMH`     | uint32   | GPS／外部时分秒，具体位编码按协议表   |
|   24 |    4 | `F_UI_SYS_Time_DMY`     | uint32   | DCMP 所在计算机日期                   |
|   28 |    4 | `F_UI_SYS_Time_SMH`     | uint32   | DCMP 所在计算机北京时间               |
|   32 |    4 | `F_UI_DCMP_Version`     | uint32   | DCMP 软件版本号，具体编码由 DCMP 定义 |
|   36 |    4 | `F_UI_DCMP_Time_DMY`    | uint32   | DCMP 编译日期，具体位编码按协议表     |
|   40 |    4 | `F_UI_DCMP_Time_SMH`    | uint32   | DCMP 编译时分秒，具体位编码按协议表   |
|   44 |    N | `payload`               | uint8[N] | 按协议版本和消息类型解释              |
| 44+N |    4 | `packetTail`            | uint32   | 包尾标志，固定为`0xB1B2A1A2`          |

## 1.3 消息类型


| 消息类型 | 对应结构体               | 数据方向   | V1 状态                             |
| -------: | ------------------------ | ---------- | ----------------------------------- |
| `0x0001` | `DcmpToDpControlPayload` | DCMP → DP | 已定义，DCMP 使用                   |
| `0x0102` | `DpToFpControlPayload`   | DP → FPGA | 表格已登记，具体实现由 DP/FPGA 负责 |
| `0x0203` | `FpgaToSpDataPayload`    | FPGA → SP | 表格已登记，可变数据域由对接方确认  |
| `0x0301` | `SpToDpPointPayload`     | SP → DP   | 表格已登记，可变数据域由对接方确认  |
| `0x0100` | `DpToDcmpTrackPayload`   | DP → DCMP | 已定义，DCMP 使用                   |
| `0x0101` | `DpHeartbeatPayload`     | DP → DCMP | 已定义，DCMP 使用                   |
| `0x0303` | `SpHeartbeatPayload`     | SP → DCMP | 已定义，DCMP 使用                   |

工作/停止不再占用独立消息类型；`F_UI_STBY_Ctrl`随完整`0x0001`控制载荷发送，1表示开始或保持采集，
0表示停止采集。历史`0xFFFF` workmode载荷不得继续发送或作为实现依据。

# 2. 内部通信

## 2.1 IP 与端口


| 项目                  | 约定                                     |
| --------------------- | ---------------------------------------- |
| 传输协议              | UDP                                      |
| DCMP 内部接收地址     | `127.0.0.1:7788`                         |
| DP/SP 发送目标        | `127.0.0.1:7788`                         |
| DCMP 向 DP 发送数据包 | 由设备台账配置，不从最近收到的数据报反推 |

## 2.2 收发流程

```text
DCMP ── 0x0001 上位机控制指令 ─────────────→ DP
DP   ── 0x0100 状态及单个航迹点 ─────────→ DCMP
DP   ── 0x0101 DP 心跳（每秒一次）────────→ DCMP
SP   ── 0x0303 SP 心跳（每秒一次）────────→ DCMP
```

DP/SP 主动发送心跳，DCMP 不主动 Ping，也不返回心跳 ACK。连续 5 秒未收到对应来源的合法心跳时，DCMP
判定其超时；报文中的时间字段不用于本地超时计算。

## 2.3 上位机控制指令：0x0001

`DcmpToDpControlPayload` 数据域固定为 896 字节，声明长度为 932 字节，完整数据报为 944 字节。


| 数据区         | 字节 | 用途                                       |
| -------------- | ---: | ------------------------------------------ |
| 通用控制信息   |  128 | 阵面组合、帧模式、量程、待机及通用处理控制 |
| 帧工作模式控制 |  128 | 景幅连续模式和单帧模式控制                 |
| 通用惯导信息   |  128 | 平台位置、姿态、速度及角速度               |
| 1号阵面控制    |  128 | 1号阵面独立控制参数                        |
| 2号阵面控制    |  128 | 2号阵面独立控制参数                        |
| 3号阵面控制    |  128 | 3号阵面独立控制参数                        |
| 4号阵面控制    |  128 | 4号阵面独立控制参数                        |

各控制字的名称、取值范围、比例尺和备份字段以协议表“DCMP-to-DP”页为准。

## 2.4 数据处理返回值：0x0100

`DpToDcmpTrackPayload` 数据域固定为 608 字节，声明长度为 644 字节，完整数据报为 656 字节。


| 数据区        | 字节 | 用途                               |
| ------------- | ---: | ---------------------------------- |
| FPGA 返回状态 |  128 | 当前阵面、帧、天线、射频及故障状态 |
| SP 返回状态   |  128 | SP 版本、编译时间及保留状态        |
| DP 返回状态   |  128 | DP 版本、编译时间及保留状态        |
| 单个航迹点    |  224 | DP 本次产生的一条航迹事实          |

FPGA 返回状态区从 `B_FP_Frame_Time` 开始，`B_FP_Packet_Count` 位于区内偏移4，
`B_FP__Antenna_Idx` 位于偏移8，方位/俯仰 S 曲线返回值位于偏移92/96，末字段 `B_FS_SF` 位于偏移124。
该区不包含包长度字段和备份字段。

外层 FPGA 状态中的阵面索引确定航迹归属。每个报文只携带一个航迹点，不设置航迹条数或航迹数组；有数据时
DP 即发送。最新版协议表仍将航迹区标为待定；当前 224 字节 `DpTrack` 继续采用已确认的 `api-track.h` 补充合同，
其中 `packFlag=1` 表示存在、`packFlag=0` 表示消亡，其他值非法。

## 2.5 DP 心跳：0x0101

`DpHeartbeatPayload` 数据域固定为 84 字节，声明长度为 120 字节，完整数据报为 132 字节。


| 载荷偏移 | 字节 | 字段           | 类型       | 定义                                                             |
| -------: | ---: | -------------- | ---------- | ---------------------------------------------------------------- |
|        0 |    2 | `dpOnline`     | uint16     | `1` 在线，`0` 不在线，其他值非法                                 |
|        2 |    2 | `fpOnlineMask` | uint16     | bit0～bit3 对应1～4号阵面；`1` 表示 FP 在线；bit4～bit15 必须为0 |
|        4 |   80 | `bak[20]`      | uint32[20] | 备份字段，发送时置零，接收方忽略                                 |

FP 在线表示 DP 能够联系对应 FP 板卡。四个阵面位彼此独立，不是互斥编号。

## 2.6 SP 心跳：0x0303

`SpHeartbeatPayload` 数据域固定为 84 字节，声明长度为 120 字节，完整数据报为 132 字节。


| 载荷偏移 | 字节 | 字段         | 类型       | 定义                                                           |
| -------: | ---: | ------------ | ---------- | -------------------------------------------------------------- |
|        0 |    2 | `spOnline`   | uint16     | `1` 在线，`0` 不在线，其他值非法                               |
|        2 |    2 | `fpDataMask` | uint16     | bit0～bit3 对应1～4号阵面；`1` 表示有数据；bit4～bit15 必须为0 |
|        4 |   80 | `bak[20]`    | uint32[20] | 备份字段，发送时置零，接收方忽略                               |

`fpDataMask=0` 只表示对应统计周期没有数据，不等同于 FP 离线。有效数据的统计窗口由 SP 实现并在联试时确认。

# 3. 外部通信

外部指控系统接口不在本版 Excel 协议中定义，因此 V1 不分配外部 `messageType`，也不复用内部消息编号。
后续只有在对接方向、端点、载荷和确认语义确定后，才在新版本协议中追加。

# 4. 接收校验

接收方按以下顺序校验，任一项失败即丢弃整个 UDP 数据报：

1. 来源符合当前设备台账配置；
2. 实际数据报长度至少包含 44 字节公共头和 4 字节包尾；
3. 包头为 `0xA1A11A1A`，协议版本为 `20260915`；
4. `F_UI_TotalLength` 等于 `36+N`，实际数据报长度等于 `48+N`；
5. `messageType` 已登记，数据域长度与对应结构一致；
6. 枚举、在线值、阵面位图和保留位满足对应载荷合同；
7. 包尾为 `0xB1B2A1A2`。

本协议不定义应用层 CRC、认证、分片、重传或可靠送达语义；部署网络和可靠性要求另行约定。
