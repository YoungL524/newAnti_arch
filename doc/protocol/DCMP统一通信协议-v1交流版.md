# 1. 通用协议

## 1.1 用途与编码

本协议用于 DCMP 与 DP/SP 的心跳、航迹及工作控制通信，以及 DCMP 与外部指控系统的数据交互。
DCMP 为上位机，DP 为数据处理程序，SP 为信号处理程序；FP 板卡状态由 DP/SP 上报，DCMP 不直接与 FP 通信。

采用 UDP，一个 UDP 数据报承载一个完整报文。新格式多字节数值使用小端，字段连续排列，无填充字节；
uint8/uint16/uint32/uint64 分别为 1/2/4/8 字节无符号整数，int32 为 4 字节有符号整数，
double 为 8 字节 IEEE 754 浮点数。所有偏移以字节计。

通用封装适用于本版心跳与拟议外部消息。现有 DP 航迹合包和工作命令保留原始格式，
不增加通用封装，不分配虚构的 messageType。新旧格式使用分别约定的端点；
不得仅凭相同包头认定兼容。

## 1.2 通用报文封装

报文总长为 **22 + N**，N 为载荷字节数。下表偏移相对整包起点。

| 偏移   | 长度（字节） | 字段          | 类型     | 定义                              |
| ---- | ------ | ----------- | ------ | ------------------------------- |
| 0    | 4      | magic       | uint32 | 0x5A5A6B6B；线上字节 6B 6B 5A 5A     |
| 4    | 4      | totalLength | uint32 | 整包长度，包含所有字段和包尾                  |
| 8    | 2      | version     | uint16 | 当前为 1                           |
| 10   | 2      | messageType | uint16 | 消息类型，不是进程内分发目标                  |
| 12   | 8      | sentUtcMs   | uint64 | Unix epoch UTC 毫秒，发送时刻；不能用于超时判断 |
| 20   | N      | payload     | bytes  | 按 version/messageType 定义        |
| 20+N | 2      | tail        | uint16 | 0xB1B1                          |

接收时核对来源、实际长度、totalLength、版本、消息类型、载荷取值和包尾。
本版不增加应用层 CRC、认证或重传字段；包头尾仅作格式检查。部署限于受控网络。

# 2. 内部通信

## 2.1 IP 与端口

| 用途      | 发送方 IP : 端口 | 接收方 IP : 端口     | 传输  |
| ------- | ----------- | --------------- | --- |
| DP 心跳   | DP：待约定      | DCMP：待约定        | UDP |
| SP 心跳   | SP：待约定      | DCMP：待约定        | UDP |
| DP 航迹合包 | DP：待约定      | DCMP：待约定，沿用兼容端点 | UDP |
| 工作／待机命令 | DCMP：待约定    | DP：待约定，沿用兼容端点   | UDP |

每个 DP/SP 来源与一个雷达组绑定，位图的 1～4 号只在该组内有效；实际地址、端口及阵面绑定在联试前填写。

## 2.2 收发流程

```text
DP ── 心跳（每 1 s）─────────────→ DCMP
SP ── 心跳（每 1 s）─────────────→ DCMP
DCMP ── 工作／待机命令 ─────────→ DP
DP ── 航迹合包（产生时发送）─────→ DCMP
```

DP/SP 主动发心跳，待机或无目标时仍发送；DCMP 不主动 ping、不回复心跳 ACK。
连续 5 s 未收到合法心跳判定相应服务掉线。航迹发送频率不等同于心跳频率或包头周期。

## 2.3 DP 心跳：messageType = 0x0101

用途：报告 DP 在线状态及四个阵面 FP 的在线状态。方向：DP → DCMP。
载荷 2 字节，整包 24 字节；表中偏移相对载荷起点（整包偏移加 20）。

| 偏移  | 字节  | 类型    | 字段           | 含义                                             |
| --- | --- | ----- | ------------ | ---------------------------------------------- |
| 0   | 1   | uint8 | dpOnline     | 1=在线，0=不在线；其他值非法                               |
| 1   | 1   | uint8 | fpOnlineMask | bit0～bit3 对应 1～4 号阵面；1=FP 在线，0=不在线；bit4～bit7=0 |

FP 在线表示 DP 能联系到该 FP 板卡。四个位独立取值，可同时置位，不是互斥编号。
dpOnline=0 是合法上报，不能因为收到报文而解释成在线。

## 2.4 SP 心跳：messageType = 0x0102

用途：报告 SP 在线状态及各阵面 FP 的数据回传情况。方向：SP → DCMP。
载荷 2 字节，整包 24 字节；偏移相对载荷起点。

| 偏移  | 字节  | 类型    | 字段         | 含义                                           |
| --- | --- | ----- | ---------- | -------------------------------------------- |
| 0   | 1   | uint8 | spOnline   | 1=在线，0=不在线；其他值非法                             |
| 1   | 1   | uint8 | fpDataMask | bit0～bit3 对应 1～4 号阵面；1=有数据，0=无数据；bit4～bit7=0 |

数据位建议统计最近 1 s 是否收到对应 FP 的有效数据，窗口待联试确认；
无目标不等于无数据，无数据不等于 FP 离线。

## 2.5 航迹合包：旧格式兼容

用途：DP 向 DCMP 回传包头、工作信息和航迹。方向：DP → DCMP。
**messageType：不适用**，保留 api.h 的 control 原始合包，不套用第 1.2 节。
每包一条 host_computer，不含航迹数组或条数字段。

下列大小按 api.h 单字节对齐、int/float=4、double/quint64=8、bool=1 推导，
联试前须与 DP 同版布局或抓包核对；旧包字节序及浮点格式也须核对。
本节不另增包尾；旧包头标识及其长度字段含义待确认。

### 2.5.1 control 整包：1165 字节

| 偏移  | 字节  | 成员                | 用途                                         |
| --- | --- | ----------------- | ------------------------------------------ |
| 0   | 768 | datapackageheader | DataPackageHeader；768 字节原有字段按随附 api.h 保持不变 |
| 768 | 68  | workstandby       | 工作控制内容回传；布局见 2.6                           |
| 836 | 329 | h_c               | host_computer；一条航迹及附属字段                    |

| 284 | 4   | time_accumulate_               | uint32 积累时间，单位待确认              |
| 288 | 8   | Track_recognition_mark         | double，历史注释称等同目标 ID；不作为分类      |
| 296 | 8   | Coming_and_going_signs         | double，历史复用为时间戳；时间基准及单位待确认     |

| 312 | 8   | Actual_or_supplementary_points | double；0 实测、1 补点               |
| 320 | 4   | Extrapolation_frequency        | int32 外推次数                     |
| 324 | 1   | Update_Flag                    | bool 线字节，业务有效性含义待确认            |

| 36  | 8   | Elevation                                      | double 俯仰，弧度           |
| 44  | 8   | RadialSpeed                                    | double 径向速度，米/秒；线符号待核对 |
| 52  | 8   | RCS                                            | double 幅值，不是 dBsm      |
| 60  | 8   | Altitude                                       | double 目标高度，基准待确认      |

## 2.6 工作／待机命令：旧格式兼容

用途：DCMP 请求 DP 开始工作或进入待机。方向：DCMP → DP。
**messageType：不适用**，沿用 workStandby 裸结构，共 68 字节，不套通用封装。
偏移相对该命令起点。

| 偏移  | 字节  | 字段                | 含义及约束                               |
| --- | --- | ----------------- | ----------------------------------- |
| 0   | 4   | Work_Standby_Mode | uint32；0 待机、1 工作；2/3 未定义            |
| 4   | 8   | Lon_Coordinates   | double；经度，旧线单位待确认                   |
| 12  | 8   | Lat_Coordinates   | double；纬度，旧线单位待确认                   |
| 20  | 8   | Altitude          | double；高度，旧线基准及单位待确认                |
| 28  | 8   | Course_Angle      | double；航向，旧线角单位待确认                  |
| 36  | 8   | Pitch_Angle       | double；俯仰，旧线单位及正方向待确认               |
| 44  | 8   | Roll_Angle        | double；横滚，旧线单位及正方向待确认               |
| 52  | 8   | Antenna_azi1      | double；天线法线方位，与 Course_Angle 的关系待确认 |
| 60  | 8   | Antenna_ele1      | double；天线法线俯仰，旧线单位待确认               |

命令没有请求编号或明确 ACK 字段。发送成功不等于执行成功，合包回显不默认作为 ACK。
完成确认和重试规则另行约定。

# 3. 外部通信

## 3.1 用途、IP 与端口

用于 DCMP 向指控系统上报目标，以及接收指控系统的目标指定。
以下 **0x0201/0x0202 为本版拟议编号，需对接双方确认后启用**。
载荷参考旧《反无雷达指控协议》，封装改用第 1.2 节；不兼容旧 32 位 command 及旧长度定义。

| 参数             | 本版约定                                   |
| -------------- | -------------------------------------- |
| 传输协议           | UDP                                    |
| DCMP IP : 接收端口 | 待约定                                    |
| 指控系统 IP : 接收端口 | 待约定                                    |
| 双方发送源端口        | 待约定                                    |
| 航迹上报周期         | 待约定；旧协议 ≤200 ms 仅作参考                   |
| 地址参考           | 旧文档 DCMP 为 192.168.1.170:4321，不作为本版默认值 |

## 3.2 收发流程

```text
DCMP ── TrackReport（0x0201，目标数据）──→ 指控系统
DCMP ←── TrackSelect（0x0202，目标编号）── 指控系统
```

目标指定只表达选择请求，本版尚未定义执行结果报文；不能据收到 UDP 包认定设备完成跟踪。

## 3.3 航迹上报：messageType = 0x0201（拟议）

用途：向指控系统上报目标位置。方向：DCMP → 指控系统。
名称：TrackReport；载荷 29 字节，整包 51 字节。偏移相对载荷起点。

| 偏移  | 字节  | 类型     | 字段        | 含义                             |
| --- | --- | ------ | --------- | ------------------------------ |
| 0   | 4   | int32  | targetID  | 对外目标编号；同一对接会话内唯一，与目标指定对应       |
| 4   | 8   | double | targetLon | WGS-84 经度，度，东经为正，范围 [-180,180] |
| 12  | 8   | double | targetLat | WGS-84 纬度，度，北纬为正，范围 [-90,90]   |
| 20  | 8   | double | targetHgt | 海拔高度，米；采用的高程基准由双方确认            |
| 28  | 1   | uint8  | optValid  | 1=使用光学角度，0=未使用；其他值非法           |

目标编号作用域、重启后的复用规则及位置无效时的处理须确认后启用；
不得直接把四个阵面可能重复的目标编号作为全局编号。
旧表中的 12/20/28/29 为累计长度，本表改为逐字段长度与起始偏移，避免误读。

## 3.4 目标指定：messageType = 0x0202（拟议）

用途：指定已上报的目标编号。方向：指控系统 → DCMP。
名称：TrackSelect；载荷 4 字节，整包 26 字节。偏移相对载荷起点。

| 偏移  | 字节  | 类型    | 字段       | 含义                           |
| --- | --- | ----- | -------- | ---------------------------- |
| 0   | 4   | int32 | targetID | 与 TrackReport 中当前有效的对外目标编号一致 |

取消选择、未知目标、重复请求及确认报文尚未定义，不借用任意负数或特殊编号表示额外命令。

## 3.5 控制命令：预留

用途：未来由指控系统下发设备控制请求。messageType、载荷、请求编号、ACK 和超时规则均待约定，
本版不分配编号，不发送空载荷占位包。
